# exp4-msg-backpressure：消息计费背压模拟

> 验证假设 6（议题 11 裂缝 2 拍板方案）：**发送者预付（按投递计费）能经济地抑制消息风暴**
> 状态：✅ 通过（2026-07-25）

## 结论先行

**发送者预付有效，且是决定性有效。** 同等失控强度下：

- 预付组风暴消息量在**预算耗尽处精确封顶**（delivered == budget，误差为 0），封顶时间随预算线性移动；
- 对照组（不计费）风暴**永不收敛**，消息量随模拟时长线性放大（72k–190k，仅受 wall-clock 限制）；
- 预付保护的不只是消息量：它保护的是**正常 agent 实际消费内容的信噪比**——预算 2k 时 SNR=0.666，且风暴死后窗口 SNR 恢复到 1.0；对照组 SNR 全程压在 0.02–0.05，永不恢复。

## 模拟模型（与议题 5/11 对齐的简化内核语义）

纯 Python 离散事件模拟器，单进程、无 LLM、无网络。

| 概念 | 模拟实现 |
|---|---|
| agent | 有余额（credits）、有界收件箱（容量=上下文窗口类比，默认 100）、按 Poisson 速率发送/处理消息 |
| Message 通道 | 定向、FIFO 有序；背压开启时收件箱满 → 投递挂起、发送方 BLOCKED，接收方消费一格唤醒最早等待者（FIFO 保持有序） |
| Topic 通道 | 广播：按订阅关系扇出，每个订阅者一份"投递" |
| 计费（发送者预付） | 每条投递从发送者余额**原子扣减** 1 credit（先扣后投）；余额不足 → 扇出在该处截断，发送方进入 BROKE 挂起；`recharge()` 可恢复 |
| 无背压对照 | 收件箱满 → 驱逐最旧消息（类比上下文窗口被冲刷），发送方永远不被阻塞 |
| 风暴场景 | 1 个失控 agent 以 50 msg/s 向 broadcast Topic 发布（20 订阅者 → 1000 投递/s 的计费强度）；20 个正常 agent 以 1 msg/s 两两直连通信；正常 agent 处理速率 20 msg/s；失控 agent 于 t=10s 起爆 |

内核忠实性：扣减原子（扇出逐条扣，余额耗尽即截断）、背压阻塞（发送方同步语义，挂起期间不能发新消息）、预算耗尽挂起（BROKE 状态直到充值）。

## 实验矩阵与度量

矩阵：**预付 on/off × 收件箱背压 on/off × 预算 {2k, 10k, 50k}**，每格 5 个 seed 取均值，模拟时长 200s。
度量：总消息量随时间曲线、正常 agent 消费的消息中有用占比（SNR，10s 滑动窗）、失控 agent 被封顶的时间点、正常通信受影响程度（有用消息投递量、正常 agent 平均阻塞时长）。

## 判定标准对照

| 判定标准 | 实证 | 结论 |
|---|---|---|
| 预付组风暴在预算耗尽处收敛 | A 组全部格子 delivered_storm == budget（2000/10000/50000，精确相等），曲线在封顶后变为水平 | ✅ |
| 对照组持续放大 | B1（free+背压）72k、B2（free 无背压）190k，均为 t 的线性无界增长；`storm_capped_at = never` | ✅ |

## 读数解读

1. **封顶是精确的，不是统计的**：delivered == budget 到个位数，因为扣减是原子的、先扣后投。风暴的爆炸半径被预算硬编码。
2. **封顶时刻 ≈ storm_start + budget / 有效投递速率**。无背压时有效速率=满速 1000/s（b10k → 20s）；有背压时失控者被收件箱拖慢到消费速率 400/s，预算烧得更久（b10k → 33s）——**机制背压不改变总量，只拉长燃烧时间**。
3. **预付保护的是信噪比，不是投递量**：四种配置下有用消息投递量都 ≈4000（正常通信的"发送"侧从未被压垮）；崩的是"消费"侧——对照组正常 agent 的收件箱被风暴消息永久占据（背压下 FIFO 排队在 100 条风暴之后）或被永久冲刷（无背压下驱逐最旧）。预付组风暴死后收件箱排空，窗口 SNR 回到 1.0。
4. **机制背压单独不够**：B1 有背压但 SNR 仍只有 0.053——背压只限速（风暴降到消费速率 400/s），不限量，风暴永远烧不完。经济背压（预付）才是让风暴**终止**的机制。两者职责清晰：机制背压保护单点接收方不被瞬时速率冲垮，经济背压让风暴在全局时间上自我收敛。
5. 预算额度是策略旋钮：预算即最大爆炸半径（b2k → SNR 0.67，b50k → SNR 0.07），与议题 11 的预算治理直接挂钩。
