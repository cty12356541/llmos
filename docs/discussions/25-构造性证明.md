# 议题 25：构造性证明——语义图灵完备的公理到定理

> 轮次：第 25 轮（2026-07-25）
> 前置：议题 20（构造性证明路径选定）、议题 21-23（本元齐备：原子/link/规格）
> 本轮任务：把证明从公理骨架展开为定理形式：原语集、可实现性引理、闭包引理、完备性定理、诚实的证明义务清单

## 一、证明目标（议题 20 边界版）

**定理（语义图灵完备，带边界）**：对于审慎型知识工作，任意信息状态变换都可表达为（Agent + Context + Tool + Channel + Memory）的有限组合。

## 二、语义指令集：八个原语变换

构造性证明需要一套"指令集"。候选八个原语（每个都是原子集→原子集的带型变换）：

| # | 原语 | 语义 | 框架实现（议题引用） |
|---|---|---|---|
| 1 | acquire 获取 | 从外部把原子拉入上下文 | tool_call（搜索/读取/问人）（议题 6） |
| 2 | generate 生成 | 从上下文原子产出新原子 | llm_call 推理步（议题 6） |
| 3 | verify 验证 | 迁移原子验证状态 | 三轨验收（确定性检查/L2 判定/人工）（议题 23） |
| 4 | relate 关联 | 断言 link 原子 | link atom 五关系（议题 22） |
| 5 | transmit 传递 | agent 间移动原子 | Message/Topic/Blackboard（议题 5） |
| 6 | decompose 分解 | 规格精化 + 委托子任务 | spawn 三划拨 + REFINES 链（议题 23/10） |
| 7 | aggregate 聚合 | 子任务结果融合为父交付 | Blackboard 融合 + lineage（议题 5/9） |
| 8 | forget 遗忘 | 原子撤出活跃状态 | 墓碑/TTL（议题 21） |

**覆盖性证据草图**（典型知识工作活动的分解）：
- 研究 = acquire + generate + verify + relate（迭代）
- 写作/报告 = generate + verify（对照规格）
- 编码 = acquire + generate + verify（确定性检查）+ relate
- 分析 = acquire + relate + generate
- 规划/项目管理 = decompose + transmit + aggregate
- 评审/QA = verify + relate
- 学习/记忆维护 = relate + aggregate + forget

## 三、引理与定理

**引理 1（原语可实现性）**：八个原语各自直接映射到已定案的系统调用与机制（上表第三列）。无需新机制——这是构造性证明的第一个非平凡观察：**本元不是为证明发明的，证明是在已建系统上发现的**。

**引理 2（组合闭包）**：框架可表达的变换对组合封闭。顺序组合由 transmit（原子经 Channel 在 agent 间流动）实现；嵌套组合由 decompose（spawn 树容纳任意深度嵌套）实现；循环由 agent 循环本体实现（步进直到规格满足或预算耗尽）。

**引理 3（规格分解可表达性）**：任何人类/组织可设计的规格树都可表达——REFINES 链记录精化、spawn 三划拨执行委托、父验收与子交付的合取关系由 IntentSpec 结构显式声明。

**定理（边界版语义完备性）**：任何人类组织可分解的审慎型知识工作任务，都可表达为八原语的有限组合。证明：任务若原子（单 episode 可完成），由 acquire/generate/verify 直接实现（引理 1）；若复合，由 decompose 分解为子任务（引理 3），对子任务递归适用，结果由 aggregate 融合（引理 2 闭包）。基例与归纳步均闭合。

**推论（自托管）**：框架可表达自身的运行时——监督 agent、调度 agent、弹性策略 agent、验证 agent 都是运行在框架上的 agent（议题 6/9/17）。递归条件（议题 20 写入定义）满足。

## 四、关键表述：可表达性，不是可判定性

必须精确：分解一个难问题**本身**是不可判定的（规划是 AI-complete）。本定理**不承诺**框架能自动找到分解——它承诺：**任何分解（无论是人设计的还是 agent 想出的）都能被框架表达和执行**。找分解的智能由 agent（或人）提供，框架提供表达与执行的完备性。这与经典图灵完备的同构：UTM 不帮你找算法，只保证你给的算法都能跑。

## 五、诚实的边界与反例压力测试

1. **隐性知识（Polanyi 悖论）**："我们知道的多于我们能言说的"。无法原子化的知识框架不能直接处理——只能经人进入（HITL=设备，议题 13）。**框架处理显性知识，隐性知识经人接地**。这是真实边界，如实记录。
2. **整体性判断**（审美、长篇连贯性）：不可分解为断言的知识——以粗粒度原子进入（生产者声明粒度，议题 21）："这部小说连贯"作为单原子，provenance=高级别判断者。框架不需要分解判断，只需要承载它。
3. **反应式控制**：界外（议题 20 已定，毫秒控制环与秒级步长矛盾）。

## 六、证明义务清单（定理的未竟部分）

1. **原语覆盖性的系统验证**：任务普查——取知识工作活动分类法（如 O*NET 工作活动分类）逐项检查可分解性，找出反例或确认覆盖
2. 引理 3 的精确表述：规格分解的"可表达性"与"可判定性"边界（已草述，需形式化）
3. 完备性的效率注记：完备性不承诺效率——某些分解的 Budget 成本可能使其实际不可行（理论可表达 vs 经济可承受，归 Budget 治理）
