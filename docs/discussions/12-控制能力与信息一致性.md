# 议题 12：控制能力与信息一致性

> 轮次：第 12 轮续（2026-07-23）
> 来源：用户在设计宗旨验证（议题 11）后指出——最大的讨论点是控制能力和信息一致性
> 题眼：**两者不是独立问题——控制的有效性依赖信息的可信度；信息的可信度依赖控制的强制力**

## 一、控制能力

### 1.1 控制通道的唯一性与控制盲区
陷阱层（LLM 调用 + 工具调用）是内核与 agent 之间**唯一的物理控制点**。一切控制原语（挂起/杀死/预算/降 tick/能力吊销/污点降级）都派生自它。
推论：**在途调用 = 控制盲区**（一次 LLM 调用挂 10 分钟、一个 shell 工具跑长命令，期间 agent 不可控）。议题 11 的三个裂缝修复恰好就是补盲区：trap timeout（裂缝 6）、max_tokens 硬顶（裂缝 7）、取消传播（裂缝 8）。

### 1.2 控制合法性来自不变量，不来自智能
内核是笨的（纯算术），agent 是聪明的（LLM）。能控制吗？能——因为**控制 = 设界，不是理解**。OS 不需要理解程序就能杀死它；内核不需要理解 agent 就能冻结预算、吊销 handle、挂起执行。"内核从不信任，只设界"在控制维度的完整表述：不变量是内核唯一的权威来源。

### 1.3 控制面提示注入——agent OS 独有的新攻击面 ⚠️
Unix 进程无法"说服"内核给自己更多资源。但 agent OS 的控制面里有 LLM（sysctl writer 调度 agent、议题 9 的语义监督 agent）——它们要**读 agent 的产物**（trace、消息、黑板内容）才能做语义决策。一个恶意/失控 agent 可以在自己的 trace 里埋注入指令，劫持调度/监督决策。
**这是控制与信息的第一个交汇点**：控制面 LLM 必须把所有 agent 产物视为污点数据——结构化输入、原始 trace 永不进指令通道（与 Policy 的污点机制合流；控制面是污点规则的最高优先级执行区）。

### 1.4 控制域的层级与批量操作
spawn 树 = 控制层级 = 故障域。批量控制是自然推论：子树冻结/子树杀死（沿继承树 walk）、按类冻结（kill all of class X）、全局 halt（挂起调度器 + 拒绝一切新陷阱）。紧急停止语义由继承树结构性支持（Kite 杀伤开关思想的系统化）。

## 二、信息一致性

### 2.1 关键拆解：agent OS 的一致性不是一件事，是三层
| 层 | 问题 | 经典对应 | llmos 的解 | 状态 |
|---|---|---|---|---|
| 状态一致性（字节级） | 共享字节是否同一份 | 分布式一致性模型 | 串行化锚点 + 分片（裂缝 3 修复） | 机制已定 |
| 血缘一致性（谁说的） | 信息来源与推导链是否可查 | 审计/溯源 | provenance 内核强制携带（议题 9） | 已定案 |
| 语义一致性（信不信） | agent 的信念是否一致 | **无对应** | **不追求统一，追求分歧可见、可追溯、可裁决** | 待拍板 |

### 2.2 语义一致性的立场：为什么不该追求统一信念
两个 agent 持有矛盾信念（A 信 X，B 信 ¬X）在经典系统里是 bug，在 agent 社会里**是常态甚至是资产**（视角多样性）。强制信念统一 = 群体思维。真正要的是：
- **分歧可见**：通过 provenance 比对发现"A 和 B 对同一主题断言矛盾"
- **可追溯**：矛盾双方各自的信息来源链可查
- **可裁决**：裁决机制在用户态——监督 agent / 投票 / 组织层级（这是组织设计不是内核机制）

这是 agent OS 与经典分布式系统的**根本分歧点**：经典系统 consistency = same view；agent OS consistency = **disagreements are explicit and adjudicable**。

### 2.3 克隆群体的记忆一致性（ELF 记忆烘焙的后续问题）
100 个实例从同一 seed 记忆 COW 分叉后各自漂移。组织更新了基础知识（新事实），100 个漂移实例怎么拿到更新？git rebase 在万级是合并冲突地狱（议题 3 的 Letta 死因）。
**解法：不可变 base + overlay 分层传播**——基础记忆作为只读共享层（与 OCI 分层镜像合流），组织更新 = 发布新 base 层版本，实例本地写在 overlay 层；rebase 仅当实例写过同 key 才冲突（COW 保证冲突面最小）。基础层共享还与 KV 前缀共享（议题 6 共享库类比）三层合流：格式层（OCI）、记忆层（base/overlay）、推理层（prefix cache）是同一个分层思想。

### 2.4 一致性也是分档购买的商品
维持一致性要烧 token（读更新、合并、重验证）。与可靠性分档（议题 9 Q4）同构：**一致性档位 = 强（串行化黑板）/ 最终（Topic 广播）/ 无（私有）**，ELF 声明任务需要哪档，Budget 付费。

### 2.5 反面警示：最危险的不是不一致，是一致地错
幻觉通过共享通道传播 = 系统**一致地**相信错误信息（议题 3 的疫情）。所以一致性传播必须有闸门：provenance-gated propagation（Policy："只有 verified 可进共享黑板"）。**无闸门的一致性放大器是负资产。**

## 三、交汇点总结

```
控制能力 ──依赖──> 信息可信（控制面读的信息不能被污染 → 污点+注入防御）
信息可信 ──依赖──> 控制强制（provenance 携带必须内核强制，否则溯源靠自觉）
```
议题 9 Q3"provenance 内核强制携带"的决策在此得到更深的 vindication：那不是可观测性设计，是**控制权的根基**。

## 四、决策点

1. 语义一致性立场：分歧可见可裁决（+一致性分档购买）vs 强制统一视图
2. 克隆记忆传播：不可变 base + overlay rebase vs git 双向合并 vs 不传播（实例各自为政）
3. 控制面防注入：控制 LLM 输入全污点化、结构化（立为内核级强制规则）vs 用户态约定

## 五、用户决策（第 12 轮，2026-07-23）——控制与一致性定案

| 决策点 | 拍板 | 落地形态 |
|---|---|---|
| Q1 一致性立场 | **参照 OS 模型（用户自定义方向）** | 语义一致性**不作为系统层概念**：①系统状态一致性=内核保证共享信息空间（串行化锚点+分片+分档保证，类比文件系统 O_SYNC/缓冲写的档位）②进程一致性=内核只管 agent 私有状态的 checkpoint/restore 自身完整性，不管信念 ③信念协调=非系统层，内核提供同步原语（黑板锁/消息有序/provenance），协调与裁决归用户态。**哲学归位：内核不管信念，只管共享状态和原语**（避免了语义一致性层的 Multics 陷阱） |
| Q2 克隆记忆传播 | **不可变 base + overlay** | 基础记忆只读共享层，组织更新=发新 base 版本，实例本地写在 overlay；与 OCI 分层/KV 前缀共享三层合流 |
| Q3 控制面防注入 | **内核级强制** | 控制面 LLM（调度/监督 agent）输入全污点化、只允许结构化数据、原始 trace 永不进指令通道——立为内核级强制规则 |

**议题 12 关闭。** 设计含义更新：议题 9 的"可裁决"机制正式划归用户态组织层；"分歧可见"由 provenance（内核强制）保留支撑。
