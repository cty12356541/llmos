# 议题 18：可观测性（压轴题）

> 轮次：第 18 轮（2026-07-23）
> 前置：议题 3 六死因中最后的设计空缺；议题 14 已给形状（/proc 类比：内核统计=只读名字绑定）
> 依赖方：L1 常备授权覆盖率度量（议题 10）、看门狗阈值调优（议题 9）、弹性策略信号（议题 17）

## 一、指标体系：agent 的黄金信号

经典 RED/USE 方法论的 agent 版：

| 类别 | 指标 |
|---|---|
| Rate | LLM 调用/s、工具调用/s、各 Channel 消息吞吐 |
| Errors | 陷阱拒绝（能力/预算）、工具失败、看门狗标记、重授权拒绝 |
| Duration | 步延迟分布、分模型延迟、队列等待 |
| Saturation | 推理槽位占用、预算树燃烧率、上下文窗口占用率 |
| **agent 特有** | **进展率**（产物/步数——花费的效率）、**成本效率**（credits/产物）、步骤重复度（看门狗信号的聚合）、**可靠性**（重试率/校验器失败率/N 版本分歧率）、**信任**（污点流量、verified 占比）、**L1 常备授权覆盖率**（自动签/上行比——议题 10 的依赖） |

## 二、trace 模型：概率系统的追踪

经典分布式追踪（request→span→tree）在 agent 世界有个免费礼物：**spawn 树天然就是 trace 树**——任务=request，步=span，父子 span 按 spawn 关系嵌套。每个步 span 记录：陷阱类型、模型、token 进出、成本、时长、工具、结果状态、污点/溯源引用。

但概率系统多一个经典没有的张力：语义调试需要内容，全量记录内容 = 存储爆炸 + 隐私问题。解法是**分层 trace**：

| 层 | 内容 | 策略 |
|---|---|---|
| L0 元数据 | span 结构数据（上表） | 常开（便宜、可聚合） |
| L1 结构化内容 | 工具参数/结果、关键决策点 | 采样（head-based N%） |
| L2 全量现场 | **agent 版 core dump**：checkpoint + 完整上下文 + 最近 N 步 trace | **异常触发**（看门狗标记/被杀/预算耗尽时自动捕获——进程崩溃产生 core dump 的直接类比） |

L2 是关键设计：**不在平时记录一切，在异常瞬间冻结现场**。确定性故障用日志，概率性故障用现场。

## 三、万级规模：源头聚合 + 拉取模型

- **内核源头聚合**：计数器/仪表/直方图在内核内维护（常开、廉价），不流原始事件——Prometheus 模型的内核版：拉指标，不推事件
- **/sys 只读绑定**（议题 14 的 /proc 类比落地）：每个节点内核暴露 /sys/agents/*，指标守护进程（用户态）抓取并逐级汇总（agent → spawn 子树 → 组织 → 全局，Prometheus federation 类比）
- **采样双制**：head-based（任务开始时按比例）+ **tail-based on anomaly**（看门狗/错误发生则回溯保留全链——稀有语义故障只能靠尾部采样抓到）
- 下钻路径由 lineage ID 保持：从组织指标 → 子树 → 单 agent → trace → L2 现场

## 四、告警与监督接口（dogfooding）

- 聚合异常检测（用户态）：燃烧率突刺、子树进展率塌陷、重试风暴、消息洪水
- **告警 = Topic 消息**：可观测性系统用自己的原语——告警发到运维 Topic，监督 agent（sysctl writer 家族）订阅裁决。狗粮吃完：Topic 的背压、兴趣过滤在此被自用
- 仪表盘/可视化：纯用户态，不在内核设计范围

## 五、内核职责（微内核原则守边界）

内核只做四件：**计数器/直方图（常开）+ 陷阱处 span 元数据发射点 + L2 core dump 触发器 + /sys 只读绑定**。存储、汇总、分析、告警、可视化全在用户态。机制=测量与暴露，策略=分析与告警。

## 六、语义可观测性——独有的最后一层

经典可观测性回答"系统慢不慢/挂没挂"；agent 可观测性还要回答"**种群在向目标推进吗**"——这是判断，归监督 LLM（已在设计中）。可观测性系统的职责是给监督者提供**语义缩放**的正确视图：组织指标 → 子树 → agent → trace → L2 现场，逐层下钻（与 skills 渐进披露同构）。

## 七、决策点

1. 内核观测机制范围：四件套（计数器/发射点/core dump 触发器//sys 绑定）vs 更胖（内核内建聚合告警）vs 更瘦（全用户态探针）
2. trace 模型：分层 trace（L0 常开+L1 采样+L2 异常触发）vs 全量记录 vs 纯指标无 trace
3. 告警通道：dogfooding（告警=Topic 消息）vs 独立告警总线

## 八、用户决策（第 18 轮，2026-07-23）——可观测性定案

| 决策点 | 拍板 | 落地形态 |
|---|---|---|
| Q1 内核观测机制 | **四件套** | 计数器/直方图常开 + 陷阱 span 发射点 + L2 core dump 触发器 + /sys 只读绑定；其余全用户态 |
| Q2 trace 模型 | **分层 trace** | L0 元数据常开 / L1 结构化采样 / L2 异常触发全量现场；确定性故障用日志，概率性故障用现场 |
| Q3 告警通道 | **告警 = Topic** | dogfooding：监督 agent 订阅运维 Topic；背压/兴趣过滤自用 |
