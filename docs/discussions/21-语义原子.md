# 议题 21：语义原子——语义计算的最小可操作单位

> 轮次：第 21 轮（2026-07-25）
> 前置：议题 19（C 类三问）、议题 20（构造性证明路径选定 → 语义原子升格为证明前提）
> 本轮任务：定义语义原子的形态、结构与操作语义

## 一、候选形态分析

| 候选 | 粒度 | 判词 |
|---|---|---|
| token/文本片段 | 太细 | 无语义身份，无法作为信念操作单位 |
| 消息/文档 | 太粗 | 一个文档含多个真假各异的断言，无法分别溯源与验证 |
| **命题/断言级（claim + envelope）** | 合适 | 单条断言 + 结构化信封；经典 KR 的粒度，但换统计主义的皮 |
| embedding 向量 | 错位 | 是表示不是原子：不可读、无溯源结构、不可文本组合 |

**符号主义陷阱的精确识别**：RDF 三元组失败的原因不是选了命题粒度，而是**把内容也形式化了**（共享本体、谓词 schema，手工对齐永无止境）。逃生口：**形式化信封，不形式化内容**——内容保持自然语言（内核永不解析），信封是结构化的（内核可管理）。这与"内核不管信念"（议题 12）是同一防火墙。

## 二、原子结构提案

```
SemanticAtom {
  id:            内容哈希（结构去重 + 完整性；语义等价不在此层，归议题 22）
  content:       不透明自然语言文本（内核永不解析）
  provenance:    { source: agent/tool/human,
                   lineage: [父原子 id 列表],   // 推导来源
                   chain_hash }                 // 血缘链完整性
  assertion:     FACT_FROM_TOOL | INFERENCE | SPECULATION | DIRECTIVE
  verification:  { status: unverified | verified | disputed,
                   by, method, timestamp }
  confidence?:   可选（模型自报或派生；内核不依赖——LLM 置信度不可校准）
  validity:      { created, ttl? }             // 遗忘机制的挂钩
  signature?:    跨组织时 DID 签名（议题 16）
}
```

**内核可对原子做的事（全部结构性，零语义）**：存储、按信封路由/过滤（断言级别/验证状态/污点级）、验证状态机迁移（unverified→verified/disputed）、血缘图遍历（接触追踪/召回）、按 TTL 遗忘、按内容哈希去重。**内核永远不读 content。**

## 三、三个关键设计决策

### 3.1 不可变性：原子即事件，信念即流
原子**不可变**。"修改"= 新原子 + lineage 指向父原子；"撤回"= 墓碑原子（tombstone）指向目标。信念状态 = 原子流上的 fold（event sourcing for beliefs）。
收益：议题 9 的"接触追踪+召回"获得数据结构——召回 = 沿 lineage 图标记后代为 disputed；审计与 replay 免费；与 Blackboard 的 git 式合并（议题 5/12）天然兼容。

### 3.2 粒度切分：生产者声明，内核接受
"一条断言多大"没有结构答案——**切分是模型侧操作**（生产 agent/harness 把输出分解为原子集），内核只接受自声明的原子。粒度策略在用户态（harness 的 harness 规范/ELF skills）。内核不变式：原子是生产者声明为原子的东西。这保持内核诚实（不猜语义），同时允许不同领域有不同粒度文化。

### 3.3 与已拍板设计的对齐
- 议题 9 的 provenance 四字段（来源/血缘/断言级别/验证状态）= 本原子信封的种子——**语义原子不是新发明，是 provenance 元数据+内容的形式化**（又一次"收敛旧概念"）
- 议题 16：外部原子带污点级进入（信封字段承接）
- 议题 8：原子转换可入 WAL（信念状态变更的可审计流）
- 议题 6：Blackboard 的原子存储成为"共享状态"的语义层实体（字节层之上）

## 四、对构造性证明的支撑（议题 20 的绑定）

有了原子，**信息状态 = 原子集合（+索引）**；**信息状态变换 = 消耗原子集 → 产出原子集**的函数（新旧原子间以 lineage 记录推导关系）。构造性证明的公理骨架因此可写：
1. 公理 A（状态）：信息状态是原子的集合
2. 公理 B（变换）：知识工作 = 原子集到原子集的映射，且产出原子的 lineage 指向消耗原子
3. 公理 C（组合）：变换可复合（Channel 传递原子、spawn 分解变换）
证明义务变成：任何审慎型知识工作任务可分解为满足 B/C 的变换序列——每个变换由（Agent+Context+Tool+Channel+Memory）实现。
