# 议题 16：网络协议栈（现代系统 3/5）

> 轮次：第 16 轮（2026-07-23）
> 前置：议题 14（外部资源同 namespace+污点分级）、议题 15（内部分布已定，联邦归本议题）、议题 2（MCP/A2A 均已入 LF 生态）
> 本议题同时关闭支线"MCP vs A2A 协议位置"

## 一、协议的位置：不是内核，是栈

分层模型：

```
agent（harness）
  ↓ 系统调用（陷阱）：msg_send / tool_call，参数是"名字"
内核：namespace 解析 → 能力校验 → 预算扣减 → 污点标记
  ↓ 绑定类型
栈（用户态，可替换）：MCP 客户端栈 | A2A 客户端栈 | 本地 IPC
  ↓ 线路
外部：MCP server | 他组织内核下的 A2A agent
```

类比精确化：
- 系统调用层 = socket 接口（稳定 ABI）
- **MCP = 设备访问协议**（NFS 客户端/SCSI initiator 的位置：驱动之上的标准化传输）
- **A2A = agent 间网络通信协议**（TCP/IP + TLS 的位置：含认证的互联协议）
- **内核不说 MCP 也不说 A2A**——内核只说"名字"和"绑定"；协议是绑定的可替换实现

对"一等公民还是适配层"的正式回答：**都不是**。内核的一等公民是 namespace 绑定；协议是绑定下面的栈层。协议死了换一个（MCP 若被新工具协议取代），内核不变——**协议演进独立性 = 通用性保全**（议题 13 判据 #2：对负载/实现的无知）。

## 二、"A note on distributed computing"在 agent 世界的一半失效

1994 年 Sun 的著名论文：本地与远程调用不可统一，四个差异——延迟（4~5 个数量级）、部分失败、并发语义、共享地址空间。RPC 假装远程=本地，于是系统在生脆中崩溃。

逐项检查 agent 语境：

| 差异 | 经典 RPC | agent 世界 | 结论 |
|---|---|---|---|
| 延迟 | 本地 ns vs 远程 ms，4~5 个数量级 | 本地 agent 调用=秒级（LLM），远程=秒级+ms | **失效**：差异淹没在 LLM 延迟里（与微内核 IPC 税同理） |
| 部分失败 | 远程死本地活 | **依然成立**：外部组织/ agent 可中途死亡 | 必须显式 |
| 信任域 | 同源代码 | **依然成立且更强**：远程输出是异组织污点数据 | 必须显式 |
| 结算 | 无 | **依然成立**：本地预付 credits，跨组织是真结算 | 必须显式 |

**设计答案：名字透明，语义显式。** 外部 agent 以本地名字绑进 namespace（位置透明的**命名**），但绑定类型可见（external/污点级），交互原语按类型适配：调用外部绑定产生**远程任务**（显式超时/escrow 支付/污点结果/部分失败状态），而不是假装它是一条本地 Message。

POSIX 同款智慧：一切都是 fd，但 socket 的 read() 和文件的 read() 返回不同的错误，select() 的存在正因为差异要紧。不欺骗，但也不分两个世界。

远程任务的失败语义：超时（ELF 声明）→ escrow 超时自动退款（议题 8 原语直接复用）；重试=用户态策略；结果默认污点。

## 三、联邦完整图景

1. **信任引导**：A2A v1.2 签名 Agent Card + DID（LF 生态已定）。组织控制面发布联邦策略：哪些 agent 对外可见（**导出绑定**）
2. **导出/导入模型**：org A 导出 agent X（签名卡片发布到联邦注册表）→ org B 的 Policy 审批后导入为外部绑定（污点级固定，TTL 租约，A2A 心跳健康检查，吊销=解绑）
3. **跨组织结算：清算所模式**——
   - B 的 agent 调用 A 的 agent：B 的 agent 付 **B 的本地 credits**（内核只记本地账，不变）
   - B 的控制面与 A 的控制面之间按周期**净额清算**（银行类比：客户各自交易，银行间清算所轧差）
   - 跨组织 escrow：释放条件的争议裁决在人/组织层（议题 8 已定：完成判定不归内核）
4. **每个调用实时 escrow 被否**：跨组织往返延迟叠加在每次调用上，且清算所模式已提供信用控制（额度+轧差）

## 四、内部控制协议（顺带钉死）

议题 15 的本地代理↔控制面需要内部控制协议（租约续约/份额/唤醒/迁移/事件）。**这是私有协议，绝不暴露给 agent**——与 A2A 严格区分。设计参照 Plan 9 的 9P：一个极简协议四个动词族（bind/lease/debit/event），9P 的教训是"一个简单协议承载一切资源访问"正是其联邦优雅的原因。

## 五、决策点

1. 协议位置：栈式分层（内核只认名字绑定）vs MCP/A2A 进内核 vs 纯外挂适配层
2. 远程语义：名字透明+语义显式 vs 完全位置透明（RPC 陷阱）vs 完全分离（双 namespace）
3. 跨组织结算：清算所净额轧差 vs 每调用实时 escrow vs 组织间预付额度

## 六、用户决策（第 16 轮，2026-07-23）——网络协议栈定案

| 决策点 | 拍板 | 落地形态 |
|---|---|---|
| Q1 协议位置 | **栈式分层** | 内核只认名字绑定；MCP/A2A 为用户态可替换栈层；协议演进独立性=通用性保全 |
| Q2 远程语义 | **名字透明 + 语义显式** | 外部 agent 本地名字进 namespace（类型可见）；外部调用=远程任务（显式超时/escrow/污点/部分失败） |
| Q3 跨组织结算 | **清算所净额** | agent 只付本地 credits；控制面周期净额轧差；每调用实时 escrow 被否 |

**议题 16 关闭。** 支线"MCP vs A2A 协议位置"一并关闭。内部控制协议定为私有 9P 式四动词族（bind/lease/debit/event）。
