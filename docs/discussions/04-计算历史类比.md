# 议题 4：计算历史类比——从专用系统到通用系统

> 轮次：第 4 轮（2026-07-19）
> 用户论点：万级规模不是空想——智能体系统正在重复计算机发展史：大型机/小型机/PC 的硬件演进，专用指令/专用系统 → 通用系统 → 现代系统的软件演进

## 类比映射表

| 计算时代 | 特征 | 智能体时代对应物 | 现状 |
|---|---|---|---|
| 专用机器（ENIAC） | 为单一任务布线 | 提示词工程 + 硬编码 workflow（手画 LangGraph 图、手排 Crew 角色） | **当下所处阶段** |
| 大型机批处理 | 昂贵、集中、专家操作、一次一作业 | 贵模型 + 集中 API + AI 工程师 + 一次跑一个流程 | 当下所处阶段 |
| 分时系统（CTSS/MULTICS/Unix） | 稀缺资源多路复用：进程、虚存、文件、用户 | **agent 内核：调度、上下文分页、IPC、权限** | **空缺** |
| PC/通用系统 | 资源便宜、通用抽象、软件生态 | 万倍资源后：agent 即进程，人人可跑千个 | 未来 |
| 现代系统 | 网络、分布式、安全、云（K8s） | agent 社会治理：身份、协议、结算 | 更远未来 |

## Sisyphus 的分析

### 支撑类比的三个论据

1. **抽象比稀缺长寿**：分时系统诞生于资源稀缺（多路复用榨干昂贵大型机），但进程/虚存/文件这些抽象在资源变便宜后不但没消失，反而成了 PC 地基。同理：今天缺的"agent 内核"抽象，在万倍资源时代仍是必需品——资源越便宜，跑的东西越多，调度越重要。**稀缺发明抽象，富足放大抽象**。
2. **harness 派正在无意识地重建 Unix 用户态**：
   - agent = 进程（活在目录里）
   - AGENTS.md = rc 配置文件
   - skills = PATH 里的可执行程序
   - MCP = 设备文件（统一接口访问外部资源）
   - A2A = socket
   - Letta MemFS = 带版本控制的 /home
   - eve"agent 即目录" = 一切皆文件

   OpenAI、Letta、Vercel 各自在重造 Unix **用户态**，但没有人在造**内核**：调度器（谁先跑谁挂起）、内存管理（上下文/KV cache 分页）、IPC 语义、用户/权限、kill switch 全部缺席。
3. **每个时代的统治 OS 都长在新硬件类别上**：大型机→MVS，小型机→Unix，PC→DOS/Windows，手机→iOS/Android，云→Kubernetes。agent 时代的"硬件" = GPU 集群 + 基础模型，其 OS 按历史规律必然出现且当前空缺。

### 类比的两个断裂处（必须正视）

1. **概率进程 vs 确定进程**：OS 管理的进程是确定性的，agent 是概率性的——
   - 进程崩溃是异常；agent 犯错是常态 → 需要的不是异常处理而是**统计性容错**（冗余/投票/校验）
   - 系统调用是精确的；agent 的工具调用是"意图近似" → 需要 Kite 式 policy 校验层
   - 进程资源消耗可预测；agent 的 token 消耗方差巨大 → 调度器面对完全不同的分布

   结论：agent OS = 经典 OS + 一层**随机性管理**，这一层没有历史先例可循。
2. **"ELF" 未定**：通用化的前提是硬件/格式标准化（冯诺依曼架构、ISA、ELF 可执行格式）。agent 时代：OpenAI 兼容 API ≈ ISA，上下文窗口 ≈ 地址空间，但**agent 的可执行格式不存在**——eve 的"agent 即目录"、MAF 的 agent 定义、AG2 的协议驱动是竞争中的候选格式。谁定义了 agent 的 ELF，谁卡住生态位。

### 历史警示（避免重蹈覆辙）

- **Multics 功能最全，输给 Unix 的"够用"**；Plan 9 思想更先进，输了；Lisp 机器的优雅败给 C/Unix 的粗暴
- 教训：**不要自上而下设计完美内核**。正确顺序是先找到最小正确抽象（进程=agent、内存=context、设备=工具），让生态自己长
- 赢的那个往往不是第一个也不是功能最全的，而是抽象最简 + 生态位最对的

## 当前结论

类比成立且有力：它解释了为什么"万级调度"是必然问题（第 3 轮），也预言了赢家的形态（内核而非库）。但两个断裂处决定了 agent OS 不会是 Unix 的简单复刻：随机性管理层和 agent 可执行格式是全新的设计空间。
