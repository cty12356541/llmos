# 议题 9：随机性管理层

> 轮次：第 10 轮（2026-07-19）
> 前置：议题 4 提出的"新大陆 #1"——概率进程如何被确定性内核调度；8 抽象中最后一块语义空白
> 核心论点：**Unix 把故障当异常，agent OS 必须把故障当统计。内核消灭不了幻觉，只提供测量、隔离、冗余原语——可靠性是用 Budget 购买的商品**

## 一、故障模型的根本不同：agent 故障 = 拜占庭故障

| | Unix 进程故障 | agent 故障 |
|---|---|---|
| 形态 | 崩溃（可观测） | **看似健康地输出错误**（幻觉/推理错/被注入） |
| 检测 | 内核直接知道 | 需要语义判断 |
| 经典对应 | crash fault | **Byzantine fault** |

拜占庭容错经典结论：容忍 f 个拜占庭节点需 3f+1 副本。但 agent 冗余有个经典 BFT 没有的问题——**相关性失败**：同模型同提示词跑 3 次，大概率犯同一个错。冗余必须**多样化**才有效（不同模型/不同提示词/不同 harness）——这是航空软件 N-version programming 的先例（空客飞控跑多套异构实现）。

## 二、容错的四档形态（成本递增，可靠性递增）

| 档位 | 机制 | 成本 | 适用 |
|---|---|---|---|
| 1. 变体重试 | 重试时改变 temperature/措辞，打破相关性 | ~1x | 默认 |
| 2. 校验器 | 生成-校验不对称：**验证常比生成便宜**（代码跑测试、数学验算）——确定性校验器最优，LLM 校验器次之 | 1.x x | 有可机械验证输出的任务 |
| 3. N-版本投票 | 3 个多样化实现多数决 | ~3x | 关键步骤（ELF 声明 criticality） |
| 4. 检查点回滚 | 检测到错误后 rewind 到出错前（语义难点：哪个 checkpoint 是"出错前"？依赖检测先行） | 存储成本 | 长任务 |

**与 Budget 的咬合**：可靠性是分档购买的商品——ELF 声明任务关键度，Budget 支付冗余倍数。内核机制（branch/join）+ 用户态策略（何时买哪档）。

## 三、Erlang 监督树——真正的大先例（但要打个补丁）

- Erlang/OTP 的 "let it crash" + 监督树（重启策略 one-for-one/one-for-all、升级链、重启预算）是分层容错的最佳实践
- **但有个关键差异**：Erlang 监督的前提是崩溃可观测；agent 的错误输出不可直接观测——**检测必须先于监督**。所以：监督树结构照抄，但触发器从"崩溃信号"换成"看门狗标记 + 校验器失败"
- 重启预算 = 另一种配额（次数限制不是金额限制）

## 四、无进展检测：内核看门狗 + 用户态语义监督（两级）

**问题**：agent 空转（livelock）——持续烧钱但无语义进展。Unix 的死循环检测（CPU 空转）在这里无效，因为 agent 每步都在"正常"调用。

**第一级：内核看门狗（watchdog）**——嵌入式硬件看门狗的移植：
- "喂狗"= 进展信号：新产物写入、新工具调用、任务清单推进、harness 显式心跳
- ELF 声明阈值：maxStepsWithoutProgress、maxRepeatSimilarity（连续步骤相似度——复读机检测）
- 到阈值 → 挂起 + 标记，转第二级

**第二级：用户态语义监督**（sysctl writer 模式复用）：
- 监督 agent 审查被标记 agent 的 trace，裁决：恢复（误报）/ 转向（注入新指令）/ 杀死（从 checkpoint 重启）
- 内核只看信号不看语义，语义判断全在用户态——符合内核边界原则

## 五、幻觉传染的隔离：溯源元数据 + 接触追踪

议题 3 的"疫情"问题的解法：

1. **溯源元数据（provenance）**：共享通道（Message/Topic/Blackboard）上的每条信息携带——来源 agent、lineage（由哪些信息推导）、断言级别（工具结果的事实 / 推理结论 / 推测）、验证状态（已经校验器验证 / 未验证）
2. **与污点追踪是对偶**：议题 6 的 taint 标记"外部不可信数据"，provenance 标记"内部断言的来源"——合起来是完整的信息血缘图
3. **类型系统类比**：verified/unverified 像类型，Policy 像类型检查器——"规划上下文只许 verified 进入"是可强制规则
4. **接触追踪 + 召回**：某 agent 被判定幻觉后，沿 lineage 前向追踪它污染了什么（接触追踪类比），Blackboard 的 git 版本化支持定位并回滚被污染条目——**食品安全溯源的信息版**

## 六、层的总架构：内核机制 vs 用户态策略

| 内核机制 | 用户态策略 |
|---|---|
| branch/join 冗余组原语 | 何时买哪档可靠性（criticality→冗余映射） |
| 看门狗计数器 + 挂起/标记 | 阈值调优、语义监督裁决 |
| 溯源元数据的管道（强制携带） | 消费规则（Policy 的"只许 verified 进规划"） |
| 比对结果的收集投递点 | 比对函数（语义 diff/测试执行/投票阈值） |

**原则**：内核不消除随机性，只让随机性**可测量、可隔离、可冗余**。可靠性购买的定价 = Budget 职责，闭环。

## 七、用户决策（第 10 轮，2026-07-19）——随机性管理层定案

| 决策点 | 拍板 | 落地形态 |
|---|---|---|
| Q1 内核机制范围 | **机制最小集** | 内核：branch/join 冗余组原语 + 看门狗计数器 + 溯源管道；比对/监督/购买决策全用户态 |
| Q2 无进展检测 | **两级制** | 内核看门狗（进展信号+ELF 阈值）挂起标记 → 用户态监督 agent 裁决恢复/转向/重启 |
| Q3 溯源元数据 | **内核强制携带** | 共享信息必带 provenance（来源/lineage/断言级别/验证状态）；Policy 可强制检疫规则（"规划只许 verified"） |
| Q4 可靠性定价 | **分档购买** | ELF 声明 criticality；默认变体重试；关键步骤买 N 版本投票；Budget 支付冗余倍数 |
