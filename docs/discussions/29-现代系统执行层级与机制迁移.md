# 议题 29：现代系统执行层级与机制迁移

## 用户原始判断

现代计算系统已经形成成熟的执行层级：

```text
Application ⊇ Process ⊇ Thread ⊇ Coroutine/Fiber
```

应用是用户面对的逻辑整体，进程是资源、隔离和故障边界，线程是宿主 CPU 的执行流，协程/Fiber 是更轻量的用户态调度单元。Agent 系统正在重新经历并发、资源稀缺、隔离、一致性、故障和分布式部署问题，因此 NLOS 应系统迁移现代 OS、runtime、数据库和分布式系统的成熟机制，而不是逐项重新发明。

## 当前定案

NLOS 执行模型正式定义为：

```text
Application
  └─ Process / IsolationUnit
      └─ AgentInstance
          └─ ExecutionFiber
              └─ Activation
```

| NLOS 对象 | 现代系统近似物 | 职责与边界 |
|---|---|---|
| Application | Application | 用户可见功能、安装、数据和权限整体；可拥有多个 Process |
| Process | Process/container/VM | 资源、生命周期、强隔离和故障边界；映射宿主 IsolationUnit |
| AgentInstance | Thread/Actor | 某 AgentRole 在特定 TaskAttempt 和 Process incarnation 中的可调度身份；不是强隔离边界 |
| ExecutionFiber | Coroutine/Fiber/Continuation | AgentInstance 内可挂起恢复的轻量执行流；在有限宿主线程上 M:N 复用 |
| Activation | Dispatch quantum/Actor turn | 一次实际执行片段，用于调度、追踪和分维计量，不拥有持久资源 |
| Operation | Future/async I/O request | Fiber await 的外部异步工作；拥有独立 cancel、deadline、幂等和副作用状态 |

Operation 不是 Fiber 的别名：Fiber 可以顺序或并行等待多个 Operation；Operation 即使调用方取消或消失，也可能因外部副作用进入 `PARTIAL_EFFECT` 或 `EFFECT_UNKNOWN`，必须独立 reconcile。

## 共享、隔离与故障语义

- 同一 Process 内的 AgentInstance/Fiber 共享地址空间、FD、runtime 和 Process 崩溃域。
- Fiber 继承 AgentInstance/TaskAttempt 的 Capability、Context、ResourceGroup 和 CancellationScope，但不自动获得新权限。
- 不互信代码必须进入不同 Process/IsolationDomain；不同 prompt、Agent 名称或 Fiber 都不构成强隔离。
- Fiber 失败可由 supervisor policy 局部处理，但 runtime panic、内存破坏或宿主线程致命错误可能终止整个 Process。
- cooperative yield 用于效率，宿主抢占、Process freeze/kill、reference monitor 和 resource controller 才是安全上界。

## Coroutine/Fiber 运行时要求

```text
CREATED → READY ↔ RUNNING ↔ WAITING_IO/MODEL/TOOL
             ↑          ↓
             └──── SUSPENDED

任一非终态 → COMPLETED | FAILED | CANCELLED
```

1. M:N runtime 使大量 waiting Fiber 不线性占用宿主线程。
2. 每次 await 绑定 OperationId、generation、cancel epoch 和 deadline。
3. callback 在唤醒前校验全部 fence，旧 callback 不能复活被取消或迁移的 Fiber。
4. child Fiber 必须遵守 structured concurrency：join、cancel 或显式 detach；detach 必须转移 owner、资源域和 supervisor。
5. Activation 分开计量 CPU active、scheduler wait、model wait、tool/I/O wait、backpressure 和 suspended time。

## 现代系统机制迁移法

采用三类迁移：

- **A 直接迁移**：capability、namespace、process isolation、queue/backpressure、WAL、MVCC、lease/fence、cgroup/job control。
- **B 语义适配**：Context working set、token/model slot、Topic interest、semantic cache、Agent checkpoint、human attention。
- **C NLOS 新机制**：typed Intent、semantic provenance/view、EffectPermit、模型不确定性与外部副作用未知态。

每个新抽象都必须先回答：现代系统中最接近什么、哪些不变量可直接继承、Agent/模型造成了什么语义断裂、为何不能由现有机制组合、如何做 conformance 与故障测试。

## 已进入 v0.5 的范围

- `Application ⊇ Process ⊇ AgentInstance ⊇ ExecutionFiber/Activation` 对象模型。
- Fiber 生命周期、M:N 复用、异步 Operation、callback fencing、结构化取消、失败传播和分维计量。
- Global → Cell → Worker → runtime 分层调度。
- GUI/NL Shell/CLI/API 对 Application、Task、Process、AgentInstance、Fiber、Resource 和 Operation 的统一控制。
- OS、runtime、数据库、分布式系统到 NLOS 的机制迁移矩阵。
- 阶段 B 的 100K dormant/waiting Fiber 验收门。

## 尚未实现和验证

这次完成的是规范落地，不是运行时代码已经具备上述能力。仍需实现并提交证据：

- M:N Fiber runtime 与 event loop；
- Operation completion queue 和 generation/cancel fencing；
- structured concurrency supervisor；
- Activation 计量和层级 ResourceGroup 归集；
- 100K Fiber、阻塞 I/O、取消竞态、Process crash 和过载 benchmark；
- GUI/NL/CLI/API 控制路径一致性测试。

因此当前可以说“执行层级和迁移方法已进入设计”，不能说“已经能在普通 PC 稳定运行十万活跃 Agent”。
