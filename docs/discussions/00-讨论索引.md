## 项目最高目标（最高优先级）

> **构建达到 Windows/macOS 级别的通用、现代、系统级 NLOS（Natural Language Operating System，自然语言操作系统）。**

这是项目所有架构取舍、阶段路线和评估建议之上的最高约束。确定性执行层、agent reference monitor、控制面和单机 MVP 都只是完整 NLOS 的启动内核与阶段里程碑，不是最终产品边界；项目不得被永久收缩为 Agent 编排框架或治理中间件。

长期系统范围包括：通用内核、现代分布式系统服务、Application/Package/Driver 模型、Artifact 与用户数据、自然语言桌面/Shell、多模态交互、开发者平台、兼容性承诺和第三方应用生态。近期实施必须克制并以证据逐级推进，但不能封死通往完整系统的演进路径。

## 用户核心论点（持续累积）

1. **最高终局**：构建达到 Windows/macOS 级别的通用、现代、系统级 NLOS；控制层只是启动内核，不得成为永久产品边界（2026-07-27 明确，2026-07-28 再确认并置于 v0.5 首位）。
2. **规模是压力测试，通用才是宗旨**：万级 Agent 验证抽象能否承压，但通用性的最终裁判是第三方能否运行设计者未预见的 Application。
3. **自然语言是首要界面，不是裸 ABI**：副作用前必须编译为 typed Intent/Action，并经过 capability、budget、consent 和 policy。
4. **终局完整、实施克制**：Application、Principal、Task、Artifact、Package、Driver、系统服务、桌面和生态均在长期范围内；当前证据从最小 strict 纵切面逐级累积。
5. **设计与事实分离**：规范定案不等于实现通过，mock、单机、真实 provider、分布式和生产证据不得混写。
6. **自动与手动控制并重**：普通用户可从自然语言顶层操作完整应用；高级用户必须像 Windows/macOS 一样下钻到 Application、Task、TaskGroup/TaskNode、Process/Agent、Resource、Topic 和 Operation 手工调度，两者共用同一 ControlCommand/Receipt 与安全边界。
7. **优先迁移现代系统成熟机制**：Agent 系统面对的并发、调度、隔离、一致性、恢复和分布式问题应先复用现代 OS/runtime/database 的控制回路与不变量；只有明确语义断裂后才新增 NLOS 抽象。

## 当前最关键未决问题

v0.5 已关闭已知 P0 的规范歧义；当前主线从“继续扩写设计”切换为“兑现第一条可强制、可持久、可恢复的端到端纵切面”：

1. **海量 Agent 的系统性**：实现 TaskGroup/TaskAttempt/AgentInstance/IsolationDomain、TaskSnapshot、唯一 CommitPermit、逐槽 EffectPermit、跨 Attempt LogicalEffect/effect-history fence、PermitAdoption/quarantine、动态 ParticipantRegistry、树状取消、bulkhead 与分片 TaskAuthority，明确“可控语义一致性”而非全局同一信念。
2. **现代 Resource Manager**：分离 ResourceGroup 与 ResourceAccount，实现 CPU/memory/storage/I/O/network/accelerator controller、多资源 AdmissionDecision、plan-level late-prepare/compensation fence、pressure/reclaim/OOM、公平与可解释 Receipt。
3. **Resource/Budget**：实现原子 reserve/consume/finalize、真实 durable WAL、流式断连结算、外部 GuaranteeTier 和并发 property test。
4. **Process/TCB**：完成 credential custody、默认拒绝 egress、pure-code 宿主抢占、LLM/Tool cancel、host-loss 与 fencing。
5. **Semantic/IntentSpec/Escrow**：迁移 exp7 到 ContentDigest/EventId 双重身份、authority-aware view、非空 hard gate，以及 DecisionCore→Notice→Release、固定 basis role/type、subject-bound TimeProof、签名 StateReceipt/CommandId reconciliation 和 Saga/outbox。
6. **KABI/应用纵切面**：以 27-entry 基础 KABI + 可选 `RESOURCE_ESCROW` 运行 signed Package → Task/Intent → spawn → Driver → Artifact/Receipt → recovery；同时交付薄 NL Shell、可信权限 UI 和最小 Task Space。
7. **PID 级执行与双路径控制**：实现 TaskPlan/TaskNode、惰性物化、Context residency、Global/Cell/Worker Scheduler、AgentInstance/Fiber M:N runtime、ScaleProfile，以及 NL/GUI/CLI/API 共用的多层 ControlCommand、Task Manager 和 Resource Monitor。
8. **证据基础设施**：建立 claim/evidence registry、canonical golden vectors、故障注入和真实 provider 复验；所有结论按范围晋升。

## 当前设计里程碑

- ✅ **最高宪法归一**：Windows/macOS 级通用现代 NLOS 是不可变终局。
- ✅ **规范源归一**：v0.5 为唯一当前架构基线，v0.1–v0.4.1 保留为历史 rationale。
- ✅ **对象模型重构**：Principal/Application/Package/Executable/Process/AgentRole/Task/Artifact 分离。
- ✅ **内核边界重构**：一等平台抽象与微内核驻留分离；Topic/Blackboard/Semantic 作为稳定系统服务。
- ✅ **关键不变量规格化**：Budget、durability、lease/fencing、semantic identity、IntentSpec、Escrow、TCB、抢占和控制面已给出 fail-closed 规则。
- ✅ **NLOS 演进路径固化**：A 启动内核 → B 单机应用平台 → C 分布式系统与 D 完整桌面并行 → E 生态；兼容、安全、证据全程横切。
- ✅ **海量执行与手动控制规格化**：TaskPlan 惰性物化、Agent 驻留分级、分层 Scheduler、ScaleProfile 和多层 Task Manager/System Control 契约进入 v0.5。
- ✅ **现代执行层级规格化**：Application→Process→AgentInstance→ExecutionFiber→Activation、异步 Operation、结构化取消和现代系统机制迁移矩阵进入 v0.5。
- ⏳ **实现与验证**：以上为设计里程碑，不代表相应代码或生产保证已经完成。

## 方向修正（2026-07-23；v0.5 于 2026-07-28 归一）

**"规模是压力测试，通用才是宗旨。"** 此前讨论漂移进治理细节（计费/escrow/重授权——大型机 MVS 气质），偏离了"设计通用系统 + 讨论现代系统"的主旨。分诊归位：

| 已有内容 | 归位 |
|---|---|
| Agent | 分离为 Application / Package / Executable / Process / AgentRole，不再一词多义 |
| Context | Artifact 的派生执行视图，不是用户数据本体 |
| Tool | Device + Driver；MCP/OpenAI/A2A 只是 adapter |
| Message/Topic/Blackboard | 一等系统服务 API；内核只保留 generic I/O、权限和资源锚点 |
| Budget/Escrow | 账本守恒和金额迁移进入不可绕过机制；定价、验收条件与合同策略留在服务层 |
| Policy/Watchdog | 语义层只输出建议；最终权限通过 capability/resource 原语生效 |
| SemanticAtom | 改为内容与事件双重身份、append-only evidence 和 policy-relative view |
| Agent ELF | 扩展为 Application/Package/Installation/UserData/Driver/UI 完整模型 |

后续主线：**先实现 strict 单机纵切面，同时从第一天保留应用、桌面、兼容与分布式接口。**
