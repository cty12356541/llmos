# 议题 8：Budget 语义细节

> 轮次：第 9 轮（2026-07-19）
> 前置：议题 5（Budget 定为一等抽象）、议题 6（内核管核算/强制/继承树，用户态管定价/分配/耗尽 handler）、议题 7（ELF 含 budget.request/exhaustion 声明）
> 本轮任务：解释 Budget 概念 + 钉死四个语义问题

## 一、Budget 是什么——概念详解

### 定义
Budget 是 agent OS 内核的**经济抽象**：agent 的一切行动（推理、工具、记忆占用）都折算成统一货币消耗，内核在陷入点原子扣减，耗尽时强制执行。它回答三个问题：**行动花什么、谁来限制、怎么追踪**。

### 为什么必须是一等抽象（不是 Policy 的子集）
1. **成本是即时的真金白银**：Unix 进程死循环浪费的是免费的时间片；agent 死循环烧的是钱。失控 agent = 财务事故不是性能事故
2. **委托链条需要问责**：A spawn B spawn C，谁付钱？没有继承树就没有问责链
3. **万级多租户**：组织跑上万个 agent，财务需要按团队/项目核算——Budget 是核算货币
4. **调度需要统一成本货币**：调度器决策"谁配得到推理槽位"需要可比较的成本单位
5. **agent 间经济行为**：A2A 的未来是付费 agent 服务，转账必须是一等语义

### 解剖结构（Budget 对象的五个组成部分）
| 组成 | 说明 | 归属 |
|---|---|---|
| 余额 balance | 当前可用量 | 内核（权威） |
| 记账流水 ledger | 每笔扣减事件（哪次调用、花多少） | 内核（热路径） |
| 继承树 inheritance tree | 父子划拨关系 | 内核 |
| 耗尽行为 exhaustion | 归零时：挂起/降级/通知 | ELF 声明 + 用户态 handler |
| 定价表 pricing | 各模型/工具的单价 | **用户态**（议题 6 已定） |

### 计价单位（unit of account）——基础决策
- 不用 token 计价：不同模型单价不同，token 不是稳定货币
- 不用法币计价：内核不该碰汇率/支付
- **用抽象 credits**：驱动在陷入点回报实际用量（X tokens，Y cached），用户态定价表折算 credits，内核只记 credits——内核与价格波动隔离

### 现实类比
手机话费套餐（预付余额 + 耗尽停机 + 家庭共享套餐=继承树）；云账户体系（AWS 主账户→子账户→预算告警）；cgroups（核算机制相同，但核算对象是钱不是 CPU）

## 二、四个语义问题的分析

### Q1：继承——spawn 时子 agent 的预算从哪来
- **A. 显式划拨**：父在 spawn 时指定切片（`spawn(child, budget=10k)`）。简单、父全权
- **B. ELF 要价 + 父审批**：子的包声明 budget.request，父（或其 Policy）批准/拒绝/调整。声明式，与 ELF 设计一致
- **C. 共享池**：父子同池不设隔离。简单但一个失控子 agent 抽干全部兄弟
- 补充机制：**回收**——父能否中途收回子未用的预算？（长期父 + 多子的场景刚需）
- 先例：k8s ResourceQuota（命名空间级）、Unix rlimit 继承（只能降不能升）、银行子账户

### Q2：耗尽响应——归零时发生什么
- **suspend**：冻结（状态保留，充值可恢复）——最诚实的失败
- **degrade**：切小模型继续跑——但能力缩水可能导致任务静默失败。**隐蔽失败 > 显式失败**（系统设计上更危险）
- **notify**：发信号，agent 自己决定（优雅收尾/主动 checkpoint/申请增资）
- 组合方案：阈值预警（80% notify）+ 耗尽默认挂起 + degrade 仅作 ELF 显式声明的可选策略（作者明确接受质量风险）

### Q3：转账清算——agent 间付费的语义
- **裸转账**：A 转给 B，完事。无追索
- **托管（escrow）**：A 的金额内核冻结，任务完成释放给 B，超时/失败退回 A
- 边界问题：内核该不该管"任务完成"的判定？不该——那是合同语义（用户态）；内核只提供原子原语：transfer、hold、release、refund（超时自动）
- Unix 类比：内核提供原子 rename，数据库在其上建事务

### Q4：联动计费——Context/KV/工具怎么算钱
- **钉住页**：按"页 × 步数"计费——钉住占用稀缺上下文空间，收费防止 pin-everything 滥用（与议题 5 的 Q3 联动落地）
- **KV 共享页**：真实成本已由推理引擎的 prefix cache 分摊（命中缓存的 token 实际更便宜——OpenAI 等 provider 就是如此计费）——**按驱动回报的实际成本记账**，不做二次分摊。共享 libc 不向进程单独收费，同理
- **工具调用**：付费 API 由工具/驱动回报成本，内核扣减
- **挂起租金**：挂起 agent 的 checkpoint 占存储——收存储租？（标记为开放问题，可后置）

## 三、用户决策（第 9 轮，2026-07-19）——Budget 定案

| 决策点 | 拍板 | 落地形态 |
|---|---|---|
| Q1 预算继承 | **ELF 要价 + 父审批** | 子 ELF 声明 budget.request → 父 spawn 时批准/调整/拒绝；支持中途回收未用预算 |
| Q2 耗尽响应 | **预警 + 默认挂起** | 80% 阈值信号（优雅收尾窗口）→ 100% 默认 suspend（充值可恢复）；degrade 仅限 ELF 显式声明 |
| Q3 转账清算 | **原子原语 + escrow** | 内核：transfer/hold/release/refund（超时自动退）；合同语义（完成判定/里程碑/争议）全在用户态 |
| Q4 联动计费 | **实际成本 + 钉页费** | 钉住页按页×步数计费；KV 共享页按驱动回报实际成本（不二次分摊）；工具按驱动回报扣减 |
