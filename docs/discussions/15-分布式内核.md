# 议题 15：分布式内核（现代系统 2/5）

> 轮次：第 15 轮（2026-07-23）
> 前置：议题 14（namespace/import/位置透明已铺路）、议题 11（陷阱层算术）、议题 12（一致性档位）
> 三个硬核问题：①内核本身怎么分布 ②agent 迁移 ③跨机一致性

## 一、问题 1：内核分布拓扑

约束：陷阱层必须中介每次 LLM/工具调用（预算/能力/污点）。跨机器时的单点与延迟问题。

**先算账（议题 11 的算术扩展到分布式）**：跨机陷阱的额外延迟 = LAN ~0.5ms / 跨机房 ~50ms，相对 LLM 调用 100ms~10s 仍是噪声；集中陷阱层吞吐 ~20k 陷阱/s 单核 > 10k agent 的 5k/s。**所以集中式在 10k 规模"算得过来"——但有两个算术解决不了的问题：可用性（内核挂=全局停）和 10k 以上的扩展。**

三个候选：

| 拓扑 | 结构 | 判词 |
|---|---|---|
| A. 集中单内核 | 一台/一组内核机，所有陷阱回源 | 简单但单点故障 + 扩展天花板 |
| B. **蜂窝式：本地内核代理（数据面）+ 逻辑集中控制面（复制）** | 每台机器跑本地陷阱代理：能力检查（缓存 namespace）、预算预扣（本地份额）、污点标记、转发驱动；控制面持有权威状态（账本/注册表/策略），逻辑集中但 Raft 式复制 | **推荐**。service mesh（Envoy+Istio）与 Kubernetes（kubelet+控制面）在万级规模验证过的架构 |
| C. 完全去中心化 | 内核状态 P2P 共识 | 账本/能力的全局一致性要共识协议，复杂度爆炸，收益不明 |

**先例的映射精度**：Envoy sidecar = 本地陷阱代理（拦截一切流量做治理）；Istio 控制面 = 下发策略/配额；kubelet = 节点代理；etcd = 权威小状态。现代系统已经替我们踩完了坑。

## 二、问题 2 之前的关键设计：租约（lease）作为分布式语义

蜂窝式成立的前提是回答"本地代理凭什么敢本地扣预算"。答案：**租约**——

1. **预算份额租约（budget chunk）**：控制面给某节点上的某 agent 发放一块预算份额（如 10k credits），节点本地扣减；份额快用完时申请补充；agent 结束/迁移时归还合并。**透支上界 = 份额大小**（与议题 11 的 max_tokens 硬顶完美兼容：本地剩余份额折算 token 上限，物理保证保留）
2. **namespace 绑定租约**：绑定带 TTL，控制面定期续约；吊销 = 不续约
3. **租约的三个红利**：
   - **优雅降级**：控制面宕机 → 系统靠未到期的租约滑行，运行中 agent 不受影响，只是不能 spawn/迁移（DHCP 租约、Kerberos 票据同款设计）
   - **故障域自动封闭**：父 agent/节点死亡 → 子的份额到期自动耗尽 → 自动挂起。**没有孤儿失控 agent**（TTL 就是自动收容所）
   - **迁移账本不动**：见下

## 三、问题 2：agent 迁移

迁移 = checkpoint + 目标机 restore + namespace 重绑定。三个子问题都有租约加持的答案：

1. **在途调用**（裂缝 8 分布式版）：**默认 drain 迁移**——等到步边界（在途调用完成并结算）再迁，与协作式调度模型一致；**紧急 evacuate**（节点将死）——取消传播（裂缝 6）掐断在途调用，按实际发生结算记损耗（裂缝 8 已定的"损耗"账目），立即迁
2. **预算账本**：账本权威在控制面，**永远不"搬"**——迁移 = 归还源节点份额 + 目标节点发新份额。租约把分布式账本问题化没了
3. **namespace 重绑定**：名称稳定、端点可变——目标机的注册表把同一名称解析到本地端点（位置透明，议题 14 的红利）。机器专属资源需要 **pinned 绑定**（类比 K8s node-affinity）：pinned 资源要么禁止迁移，要么迁移后代理回源（性能换可达）

附带说明：迁移后 KV 前缀缓存是冷的——性能问题不是正确性问题，驱动的业务。

## 四、问题 3：跨机一致性——议题 12 的档位就是分布策略

议题 12 已定"系统状态一致性分档"。分布式落地：**一致性档位 = 分布策略**——

| 档位（议题 12） | 分布式模型 | 机制 |
|---|---|---|
| 强（strong） | **主副本串行化**（primary-copy） | 每个黑板有 home 节点，写路由到 home 排序；读可本地缓存+版本校验。热点问题由议题 11 裂缝 3 的命名空间分片天然负载均衡（不同黑板不同 home） |
| 最终（eventual） | **多主 + merge driver** | 议题 12 已选的 git 式合并模型天然就是多主——跨机复制、冲突走 merge driver |
| 无（none） | 本地黑板 | 不跨机 |

wakeup 原子性跨机：写在 home 提交与唤醒阻塞读者保持原子（home 经控制面事件通知各机本地代理唤醒）；增加的只是 ms 级通知延迟，对秒级 agent 步长无感。

**Raft-per-blackboard 被否**：v1 不需要每个黑板一个共识组，主副本足够；关键控制面状态（账本/注册表）才需要 Raft 复制。

## 五、联邦 vs 内部分布（为 3/5 铺路）

本议题解的是**内部分布**（一个组织、多机器、一个控制面）。**联邦**（多组织、多控制面）走另一条路：org B 的 agent 以污点外部绑定进 org A 的 namespace（议题 14 已定），控制面之间靠 A2A 签名 Agent Card + DID 互信，跨组织结算用 escrow（议题 8 已定）。这是"agent 互联网"，归网络协议栈议题（3/5）。

## 六、决策点

1. 拓扑：蜂窝式（本地数据面+逻辑集中控制面）vs 集中单内核 vs 去中心化
2. 预算分布：份额租约 vs 每陷阱回源（强一致但单点+延迟）vs 本地乐观+事后对账
3. 跨机黑板：一致性档位=分布策略（强=主副本/最终=多主合并）vs 统一主副本 vs 统一共识组

## 七、用户决策（第 15 轮，2026-07-23）——分布式内核定案

| 决策点 | 拍板 | 落地形态 |
|---|---|---|
| Q1 拓扑 | **蜂窝式** | 本地内核代理（数据面：能力检查/预算预扣/污点/转发）+ 逻辑集中控制面（账本/注册表/策略，Raft 复制） |
| Q2 预算分布 | **份额租约** | 控制面发份额、节点本地扣、耗尽申请、迁移归还合并；透支上界=份额；绑定带 TTL；红利：优雅降级+故障域自动封闭+迁移账本不动 |
| Q3 跨机黑板 | **档位 = 分布策略** | 强=主副本串行化（home 节点）、最终=多主+merge driver、无=本地；Raft 仅用于控制面小状态 |

**议题 15 关闭。** 迁移语义随定：默认 drain（步边界）、紧急 evacuate（取消传播+记损耗）、pinned 绑定处理机器专属资源。内部分布闭合；联邦归议题 16（网络协议栈）。
