# 议题 17：弹性与多租户（现代系统 5/5，收官）

> 轮次：第 17 轮（2026-07-23）
> 前置：全部现代系统前置议题；本题为系列收官，大部分是已定决策的收口
> 注：4/5（service mesh 同构）核心内容已被议题 15 拓扑论证吸收，不单立

## 一、弹性（Elasticity）

### 1.1 弹性的三维模型
经典云弹性只有一个维度：实例数（HPA）。agent OS 有三个：

| 维度 | 机制（已定） | 效果 |
|---|---|---|
| 实例数 | spawn/suspend/resume | 水平扩缩 |
| tick 速率 | 议题 6 调度机制（降 tick） | 不增实例，降背景 agent 的推理频率让出槽位 |
| 模型档位 | LOD 调度（议题 6/9） | 高峰期关键路径用大模型、背景降小模型 |

三维组合：成本压力下先降档、再降 tick、最后才减实例（减实例有状态成本）；负载高峰先升 tick、再增实例。

### 1.2 三个收口中的新性质
1. **预算树 = 弹性的天然刹车**：弹性扩缩在预算继承树内进行，总量被根预算物理封死。云的"serverless bill shock"（自动扩容烧穿账单）在本架构中**结构性不可能**——最多把预算烧完，然后 80% 预警、挂起（议题 8 已定语义接管）
2. **记忆烘焙让弹性实例带经验上岗**：从 ELF 镜像 spawn 新实例 = 带 seed 记忆 + COW（议题 7）。云的 cold start 痛点（新实例从零开始）在此被化解为"新实例从组织经验开始"
3. **scale-to-zero = 挂起而非销毁**：闲置 agent 挂起（checkpoint 保留，议题 8），回暖即恢复且记忆连续。预热池（warm pool）= 预 spawn + KV 前缀缓存预热（Lambda warm pool 类比，但我们的"预热"包含记忆与 KV 两层）

### 1.3 弹性的决策者
机制在内核（spawn/suspend/tick/档位），**策略在用户态：弹性策略 agent**（sysctl writer 家族的新成员）——监视信号（Topic 队列深度、Message 积压、预算燃烧率 vs 进展、看门狗标记率），慢循环调参。信号全是议题已定的结构信号，零新机制。

## 二、多租户（Multi-tenancy）

### 2.1 租户 = 三棵树的根
组织 = spawn 树、预算树、namespace 三棵树的根。租户接入 = 签发根信封 + 根预算 + 根 namespace（议题 10 衰减链的顶端）。隔离天然成立：namespace 互相不可见（议题 14）、预算互不可动（独立根）。

### 2.2 真问题：共享物理层的吵闹邻居
逻辑隔离有了，但租户共享物理设施（推理槽位、内核、驱动）。租户 A 的洪流不能饿死租户 B：
- **加权公平共享**（cgroup CPU shares 类比，且层级化：租户份额 → 租户内再分）：调度器的租户间权重是 sysctl 可写参数，LLM 调度 agent 在组织 Policy 界内可调
- **多维配额**（k8s ResourceQuota 类比）：credits、agent 数上限、spawn 速率、黑板存储、消息速率——硬限制，挂在租户根上
- **计量归账**：账本天然按 agent 记账（议题 8），租户级汇总是用户态会计服务

## 三、决策点

1. 弹性模型：三维弹性（实例×tick×档位）vs 经典一维 HPA（只调实例数）
2. 弹性决策归属：用户态弹性策略 agent（sysctl writer 家族）vs 内核内建自动伸缩规则
3. 租户公平：加权公平共享+多维配额 vs 严格分区（固定切片，无弹性借用）

## 四、用户决策（第 17 轮，2026-07-23）——现代系统系列收官

| 决策点 | 拍板 | 落地形态 |
|---|---|---|
| Q1 弹性模型 | **三维弹性** | 实例数×tick×档位联动；成本压力先降档→降 tick→减实例；高峰先升 tick→增实例 |
| Q2 弹性决策 | **用户态弹性策略 agent** | sysctl writer 家族新成员；监视结构信号慢循环调参；内核只供机制 |
| Q3 租户公平 | **加权共享 + 多维配额** | cgroup shares 层级化 + ResourceQuota 挂租户根；账务汇总用户态 |

**现代系统系列收官（5/5）**：namespace → 分布式内核 → 网络协议栈 → （service mesh 已吸收）→ 弹性与多租户。
