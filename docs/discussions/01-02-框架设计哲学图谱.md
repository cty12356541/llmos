## 一、核心分析框架

三大框架的分歧本质上是 **"谁来控制控制流"** 的哲学分歧：

- **LangGraph：程序员控制** —— 智能体 = 显式状态机/图，LLM 只是节点里的函数
- **AutoGen：LLM 控制** —— 智能体 = 对话参与者，流程由"谁该说话"的 LLM 决策驱动
- **CrewAI：隐喻控制** —— 智能体 = 公司员工，用角色/任务/层级的组织学隐喻隐式约束流程

### 哲学家族（2026-07 核查后修订版）

| 家族 | 核心立场 | 代表框架 |
|---|---|---|
| A. 显式控制流派 | 流程由代码结构保证，不信 LLM 自主路由 | LangGraph、ADK 2.0(新加入)、MAF Workflows、Pydantic AI |
| B. 涌现/组织隐喻派 | 流程由对话或组织隐喻涌现 | AutoGen(维护模式)、CrewAI、CAMEL；MetaGPT 已休眠 |
| C. 模型厂商极简派 | 模型够强，编排就该薄 | OpenAI Agents SDK（**已转向 harness+沙箱**） |
| D. 状态/记忆本体派 | 智能体的差异化在状态管理 | Letta（**已转向 harness+git 化记忆**） |
| E. 分布式/企业运行时派 | agent 运行时 = 已解决的分布式系统问题 | MAF、Dapr Agents、Agno(AgentOS)、AWS Loom |
| F. 低代码平台派 | workflow 够用，agent 是流程中的节点 | Dify（**正扩张为 agent 平台**） |
| **G. Harness/沙箱派（2026 新阵营）** | agent = 模型 + 文件系统 + shell + 沙箱 + skills，编排让位于环境 | OpenAI Sandbox Agents、Letta Code、Vercel eve、Dify Agent、Kite |

**2026 年最重要的格局变化**：家族 G 的出现使战场从"图 vs 对话"演变为 **"harness/文件系统/沙箱" vs "图编排" 两大阵营**，MCP（工具）+ A2A（智能体间）成为两派共用的协议底座（两者均已进入 Linux Foundation 体系）。

## 二、各框架设计哲学要点（含 2026-07 核查修正）

### LangGraph：图即程序，状态即一等公民
- 借鉴 Pregel 模型：节点计算、边转移、super-step 间消息传递
- 刻意不提供 Agent 抽象；共享 State + reducer；持久化一等公民（Checkpointer）
- **【核查】** 1.0 于 2025-10-17 发布（稳定化，承诺 2.0 前无 breaking）；高层 agent 构建上移到 LangChain `create_agent`（带 middleware，底层跑在 LangGraph 上）；**"LangGraph Platform" 已改名 "LangGraph Server"**；1.1（2026-03）opt-in 强类型流式；1.2.x 增加节点级 timeout、错误处理器（Saga/补偿模式）、DeltaChannel

### AutoGen：一切皆对话 → 已三线分裂
- **【核查修正】** 不再是一个项目，而是三条线：
  1. 微软 AutoGen 仓库：2025-10 起**维护模式**（仅 bugfix），官方引导去 MAF
  2. **Microsoft Agent Framework（MAF）1.0 于 2026-04 GA**（Python/.NET），AutoGen+SK 的官方继任者，含图工作流、中间件、A2A+MCP 互操作
  3. AG2 社区分叉：v1.0.0b0（2026-07）激进重构为**协议驱动**框架，Classic（ConversableAgent 体系）被移除；PyPI 陷阱：`pip install autogen` 现在装的是 AG2
- 哲学教训不变：涌现派的 GroupChat 魔法被工程现实击败

### CrewAI：组织隐喻优先
- 角色扮演即提示工程模板；后加 Flows = 承认确定性控制流绕不开（收敛信号 #1）

### OpenAI Agents SDK：从"薄"到"harness" ★ 重大修正
- ~~原判断：极简四原语薄客户端~~（已过时）
- **【核查修正】** 2026-04-15（v0.14）方向性扩展：**model-native harness + Sandbox Agents**——`SandboxAgent`/`Manifest`，原生沙箱后端（本地 Unix/Docker/E2B/Modal/Cloudflare/Vercel 等），原语包括 MCP 工具、skills 渐进披露、AGENTS.md、shell 工具、apply_patch、跨运行沙箱记忆
- **哲学信号**：OpenAI 把 Codex 的 harness 思路下沉进 SDK——"文件系统+shell+patch+skills+沙箱"成为一等公民，是对"agent=编排图"路线的明确背离。Swarm 已彻底废弃

### Google ADK：反向而行，转向图工作流 ★ 重大修正
- **【核查】** ADK 2.0 GA（2026-05）：**图工作流引擎 + 动态工作流**——确定性路由（代码求值的条件边、HITL）与 LLM 节点分离，官方明确宣称"execution routing 与 language processing 解耦"（安全论据：限制提示注入的爆炸半径）
- **有意思的对位**：OpenAI 从编排走向 harness，Google 从 agent 树走向图——两家向对方的起点走

### smolagents (HF)：code agents 路线坚挺
- **【核查】** v1.26.0（2026-05），CodeAgent 仍是默认路线，28k+ stars，沙箱后端（E2B/Modal/Docker/Blaxel）成熟
- 影响力佐证：OpenAI SDK 的 code mode、Dify Agent 的沙箱路线都在向 code-as-action 收敛，smolagents 是开源参照物

### Letta：从"agent-as-service"到"stateful harness + git 化记忆" ★ 重大修正
- ~~原判断：MemGPT 记忆分页 + REST 常驻服务~~（已过时）
- **【核查修正】** 原 Python server 已成 legacy（V1 API）；活跃开发转向 **Letta Code**（TS，stateful agent harness）：agent 有记忆/身份/经验感，能重写自己的 memory/skills/prompts 甚至 harness 本身
- 记忆架构重建：**MemFS / Context Repositories（2026-02）**——记忆块投射为本地 markdown 文件、**git 版本化**、多子智能体通过 worktree 并发写记忆再 merge；内置 dream（睡眠反思）/defragmentation 技能
- **哲学演进**：OS 类比没变，但"虚拟内存"的实现从工具调用变成了**文件系统 + git**——这与 harness 派完全合流

### MetaGPT：休眠
- **【核查】** 最后 release v0.8.2（2025-03），org 更名 FoundationAgents，精力在商业产品 MGX。SOP 哲学仍有思想价值，但项目实体已边缘化（推断，无官方 EOL）

### Dify：向 agent 平台扩张
- **【核查】** v1.16（2026-07-17）推出 **Dify Agent（Beta）**：Linux 沙箱 + Skills 系统 + 代码/shell 执行，可嵌入 Workflow 节点——低代码平台派也在向 harness 派靠拢（收敛信号）

### 2026 新玩家（有哲学主张的）
- **Vercel eve**（2026-06，beta）：**filesystem-first durable agents**——agent 即目录（instructions.md + tools/ + skills/ + channels/ + schedules/），文件系统是唯一编排界面，"convention over configuration"
- **Kite**：**"LLM 不可信"内核派**——LLM 只提议不执行，内核按 policy 校验每个动作，熔断/杀伤开关/幂等内建
- **Mastra 1.0**（2026-01）：TypeScript 阵营事实标准（LangGraph 的 TS 等价物）
- **AWS Loom**（2026-07，基于 Strands）：企业级 paved-path，明确"**不在运行时生成代码**"的安全主张——与 harness 派针锋相对
- **sovereign-agent**：教学库，提炼 Claude Code/OpenHands 等的"八个架构决策"——"prompts are advisory; registries are physics"

## 四、对"运行时框架"最关键的判断（修订版）

1. **2026 形成两大设计阵营**：**harness/文件系统/沙箱派**（OpenAI SDK、Letta Code、eve、Dify Agent、Kite）vs **图编排派**（LangGraph、ADK 2.0、MAF）。前者的信条：智能体的能力来自环境（文件系统、shell、skills、记忆文件），编排是多余的；后者的信条：生产可靠性要求控制流显式化、与 LLM 解耦。你的运行时框架必须首先回答站哪边、还是做桥。
2. **"状态"的定义被 harness 派重写了**：Letta 的 MemFS（git 化记忆文件）、eve 的"agent 即目录"、sovereign-agent 的"session 即目录"——**文件系统正在成为状态管理的最大公约数**，git 成为多 agent 并发写状态的协调机制。这和我之前说的"Letta 管状态 × Dapr 管实体"两条轴相比，harness 派给出了第三条答案：状态即文件，实体即进程。
3. **安全模型正在两极化**：Kite/AWS Loom 主张"LLM 不可信/不生成运行时代码"，内核按 policy 校验；harness 派主张"给 LLM 完整环境 + 沙箱隔离"。ADK 2.0 的"路由与语言处理解耦以限制提示注入爆炸半径"是中间路线。运行时框架的安全架构必须显式选型。
4. **协议底座已统一**：MCP（agent↔工具，AAIF/Linux Foundation，2025-12 捐赠）+ A2A（agent↔agent，LF 项目，v1.2 签名 Agent Card+DID）。新运行时不需要发明协议，但要决定协议在架构中的位置（是一等公民还是适配层）。
5. **行业收敛信号增至 5 个**：微软合并 AutoGen+SK、CrewAI 加 Flows、Dify 降级 agent 为节点、**AutoGen 三线分裂且官方继任者是图工作流**、**Dify/OpenAI 双双补沙箱**——确定性底座 + 受控自主 + 沙箱执行，已是三方共识。
