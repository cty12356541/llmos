# 议题 3：万级规模——资源翻万倍后，现有框架能否调度上万智能体？

> 轮次：第 3 轮（2026-07-19）
> 用户提问：如果可供调度的资源突然翻万倍，现有智能体框架能否同时调度成千上万个智能体？

## 结论

**不能。死法不是"调度不动"，而是压根没有"调度"这个概念。** 现有框架全是库（library），没有一个是内核（kernel）：无准入控制、无优先级、无抢占、无配额、无资源核算——它们默认算力无限且免费，万倍资源假设恰好炸掉这个默认。

## 场景拆分（答案完全不同）

- **场景 A：一万个互不通信的 agent（批处理型）** → 今天就能。但这不需要 agent 框架：队列 + worker 池 + vLLM continuous batching 即可，本质是尴尬的并行推理，框架是累赘
- **场景 B：一万个互相协作的 agent（组织/社会型）** → 集体阵亡，算力无限也救不了编排层

## 框架尸检表

| 框架 | 死因 | 死亡数量级 |
|---|---|---|
| CrewAI | 顺序/层级 Process 语义本身反并发 | ~100 |
| LangGraph | 单进程 asyncio + 每 super-step 全量 checkpoint 写放大 | ~1k |
| AutoGen 系 | pub/sub 广播通信 O(n²) | ~1k |
| Letta/MemFS | git 合并协调在 10k 并发写下是冲突地狱 | ~1k |
| OpenAI SDK/harness 派 | 每 agent 一个沙箱进程，10k 沙箱的调度回收无设施 | ~几千 |
| Dapr Agents | 活得最久（virtual actor 百万级设计，Orleans 血统），但只有实体生命周期管理，无 agent 专属调度语义 | 可能撑到 10k 但裸奔 |

## 算力无限时剩下的瓶颈清单

1. **调度语义真空**：没有框架能回答"谁先跑、谁挂起、谁超预算、谁该被杀死"——OS 的核心职能（稀缺资源分配）在框架层完全缺席。万倍资源不会让问题消失，会让它从"不存在"变成"核心矛盾"
2. **通信拓扑爆炸**：广播/群聊 O(n²)；人类社会靠层级/部门/信息局部性解决，没有框架把"通信局部性"当一等概念
3. **状态一致性**：10k agent 读写共享状态时，checkpoint 写放大、记忆合并冲突、一致性模型全无答案
4. **非确定性传染**：单 agent 幻觉是 bug，幻觉经消息传给 500 个下游是疫情；无隔离/检疫/熔断语义
5. **可观测性崩溃**：万级 agent 只能靠聚合指标 + 采样 + 异常检测——"agent 版 Prometheus"不存在
6. **治理 > 算力**：token 预算是货币，A2A 签名 Agent Card + DID 成刚需（身份、防劫持）

## 现成答案行业：游戏服务器

MMO 早已解决"一万个 AI 实体同场"：interest management（只向相关实体广播）、tick rate 分级、AI 的 LOD（视野外用简化逻辑）。翻译过来：低优先级 agent 用小模型/少 token/低频调度——**"智能"本身成为可分级调度的资源**。此概念在现有 agent 框架中完全缺席。

## 对本项目的含义

万级规模失效不是工程不努力，是**抽象层级错了**：应用库 vs 内核。这个位置今天是空的——这是运行时想法最强的立项论据。
