# 议题 10：重授权签字链——"谁签字"

> 轮次：第 11 轮（2026-07-23）
> 前置：议题 7 定案"分段可变性声明"（记忆自由 / skills 允许 / 核心指令高门控 / 工具+权限修改必须重授权 requiresReauth），但运行时重授权流程"谁签字"未定
> 本轮任务：设计重授权的权限来源、分级结构、时效语义

## 一、问题精确化

agent v1 持有一组能力（工具 handle + 权限），v1 → v2 的自我修改触及 requiresReauth 段（工具/权限声明变更）时，v2 的能力请求必须重新获得签字。问题：**谁有权签？**

候选签字人：
1. **人类操作员**：最安全，但万级 agent 高频自修改时是瓶颈，不 scale
2. **组织 Policy 守护进程**：自动化规则引擎（类比 polkit/OPA），scale 但只能覆盖规则能预见的情形
3. **父 agent**：spawn 链上的直接授权者

## 二、核心洞察：衰减原则（attenuation）结构性地回答了"谁签字"

能力安全（capability security）的经典原则：**委托只能衰减，不能放大**——父 agent 只能把自己能力信封（envelope）的子集授予子 agent。

推论（这是本轮的关键设计判断）：
- **内核可以机械校验**：v2 请求的能力 ⊆ 父的当前信封？纯集合包含判断，零语义——完美符合"内核从不信任，只设界"
- **扩权请求物理上无法被父批准**：父签不出自己没有的能力。扩权只能沿授权链**上行**回溯到信封源头——最终必达组织根（人类/根 Policy）

## 三、分级签字链提案

| 层级 | 情形 | 签字人 | 时效 |
|---|---|---|---|
| L0 内核不变量 | 一切重授权 | 内核机械校验：请求 ⊆ 父信封（集合包含） | 同步、必过此关 |
| L1 常备授权（standing authorization） | 信封内的低风险变更（如：从组织批准注册表添加 tier ≤ 2 的只读工具） | **Policy 守护进程按预批规则自动签** | 即时（规则预批，无需等待） |
| L2 上行扩权 | 请求超出父信封（新域网络访问、权限范围扩大、核心指令变更） | **沿链上行至信封源头，最终人类/组织根** | 同步阻塞，agent 挂起等待 |

**规模化关键概念：常备授权**——绝大多数重授权是规则可预见的，Policy 守护进程的规则就是"预先签好的字"。人类只见例外。这回答了"人类是瓶颈"的反对：人类不签常规，只签扩权。

## 四、两个配套机制

1. **skills 修改为什么不需要重授权**（与议题 7 的一致性核查）：skills 修改只改变 agent **如何使用**已有能力 handle，不增加 handle。内核按"能力集合是否变化"判定是否需要重授权，不按"包内容是否变化"——能力视角而非文件视角
2. **审计流水**：每次重授权事件强制记录（请求方、签字方、能力差分、lineage 位置）——与议题 9 的溯源管道合流，安全事件可回溯

## 五、与现有设计的咬合

- Budget 继承树（议题 8）与授权信封树同构：spawn 时同时切预算片和信封子集——**spawn 就是一次"双划拨"**
- ELF 的 requiresReauth 声明（议题 7）= 格式层契约；本议题 = 运行时执行机制
- sysctl writer（议题 6）：Policy 守护进程的规则更新也走"用户态策略写参数、内核机械执行"的同一模式

## 六、遗留风险点（诚实清单）

1. **信封粒度的设计压力**：父给子的初始信封划多大？划大了衰减形同虚设，划小了频繁上行。需要"组织标准信封模板"（按 agent 角色预定义）——但这是部署策略不是内核机制
2. **L1 规则引擎的完备性**：规则写漏了 = 常规变更被打回 L2 = 人类瓶颈回归。规则引擎需要覆盖率度量和持续维护
3. **上行延迟**：L2 人类签字的延迟是分钟~小时级，扩权中的 agent 长时间挂起——挂起期间的 Budget 计费（议题 8 的开放问题"存储租金"在此重现）

## 七、用户决策（第 11 轮，2026-07-23）——重授权定案

| 决策点 | 拍板 | 落地形态 |
|---|---|---|
| Q1 签字链模型 | **衰减 + 三级签字** | 衰减原则进内核（请求 ⊆ 父信封，机械校验）；L1 常备授权（Policy 守护进程规则预批，人类只见例外）；L2 上行扩权沿链至源头人类 |
| Q2 扩权等待期 | **v1 续跑 + 热切换** | 蓝绿部署类比：旧授权版继续服务，v2 挂起等待，批准后原子热切换，服务不中断 |

**议题 10 关闭。** Policy 抽象语义全部闭合。遗留：组织级信封模板（部署策略，非内核机制）；L1 规则覆盖率度量（可观测性议题联动）
