抽象比稀缺长寿

分时系统诞生于资源稀缺，但进程 / 虚存 / 文件在资源变便宜后成了 PC 地基。稀缺发明抽象，富足放大抽象。

harness 派在重建 Unix 用户态

agent = 进程，AGENTS.md = rc 配置，skills = PATH 可执行程序，MCP = 设备文件，A2A = socket。但没有人在造内核。

历史警示：Multics 教训

Multics 功能最全，输给 Unix 的「够用」；Lisp 机器的优雅败给 C/Unix 的粗暴。先找到最小正确抽象，让生态自己长。

Problem/ 02

现有框架全是库，没有一个是内核

立项问题：如果可供调度的资源翻万倍，现有框架能否同时调度成千上万个智能体？答案是不能——死法不是「调度不动」，而是压根没有「调度」这个概念：无准入控制、无优先级、无抢占、无配额、无资源核算。规模在这里是压力测试：它压出的是通用性缺口。

Autopsy · 语义缺失

万级规模失效不是工程不努力，是抽象层级错了——应用库 vs 内核。OS 的核心职能（稀缺资源分配）在框架层完全缺席。万倍资源不会让问题消失，会让它从不存在变成核心矛盾。这六大死因的逐一闭合，见支撑与验证 · 宗旨验证。

Direction/ 03

规模是压力测试，通用才是宗旨

v0.2 的方向修正：规模不是目标，是检验手段。主线因此排成两步——先证明通用，再展开现代。

规模压出的是通用性缺口

万倍资源不会让问题消失，会让它从不存在变成核心矛盾。万级失效的死因不是「调度不动」，而是没有「调度」这个概念——这指向抽象层级的错误，不指向工程努力不足。所以万级规模只是压力测试：它压出的每一道裂缝，都是通用性判据的输入。

主线两步走

第一步设计通用系统：判据可检验，16/16 重构测试通过，治理语义归位为可插拔用户态模块——Budget 是设施不是灵魂。第二步展开现代系统：namespace、分布式内核、网络协议栈、弹性多租户、可观测性全部定案。

通用性四判据与 16/16 重构测试，见通用内核 · 通用性论证。
