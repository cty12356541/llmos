Stage B/ 02

第一次成为真正的通用操作环境

阶段 B 不是“更多 Agent 功能”，而是从可信 runtime 迈向第三方应用平台。

应用与数据

Application、Package、Installation、Update、Artifact、UserData container、Identity、Search、Notification。

任务与执行

TaskPlan/TaskNode、TaskGroup/Attempt、Process、AgentInstance、ExecutionFiber/Activation、async Operation。

资源与恢复

ResourceGroup/Account、Context residency、checkpoint/evict/rehydrate、single-node SchedulerDomain。

用户与开发者

SDK、CLI、debugger、conformance kit、Task Space、Task Manager、Resource Monitor、可信权限 UI。

阶段 B 退出门不是“页面能跑”。

第三方必须能在不修改内核的情况下安装和运行陌生 Application；10K/100K TaskNode、100K waiting Fiber、取消竞态、唯一提交、压力回收和 GUI/NL/CLI/API 控制同路都必须有 Evidence。

Candidate Baseline/ 03

技术栈服务于对象模型，不能反向定义系统

当前技术选择属于 candidate/PoC。Tokio task、SQLite row、Wasmtime resource 或 Tauri command 都不能替代 NLOS 的稳定身份和契约。

Rust核心 TCB、nominal ID、状态机、Resource、Supervisor、Driver host 与 CLI
Tokio + RuntimeAdapterM:N Fiber/异步执行引擎；NLOS identity、cancel、metering 留在 facade
Process + Wasmtime/WASI第三方组件的 capability-oriented、跨语言、双层隔离候选
SQLite WAL + CAS Artifact阶段 B 单机权威状态与内容寻址数据；必须通过 kill/torn-write/recovery
Protobuf / WIT / CBOR服务 IDL、组件接口与签名 canonical object 各司其职
Tauri + Web UITask Manager/Resource Monitor 候选；最终授权仍由 SystemControl 校验
Evidence Ladder/ 04

所有能力声明都有证据等级

D

DESIGN

规范中定义了对象、不变量、状态机和验收条件；不代表代码存在。

T

TESTED

在明确 commit、环境和 workload 下通过测试；不得外推到未测平台和规模。

C

CONFORMANT

满足 profile applicability、golden vectors、故障测试和 Evidence registry。

P

PRODUCTION EVIDENCE

具备真实工作负载、长期运行、故障恢复、安全和运维证据。

Current State/ 05

现在已经有什么，还缺什么

v0.5 当前规范、最高目标、对象模型、海量执行与控制、现代系统迁移矩阵、项目管理与渐进知识 CRUD、阶段 B 技术讨论、Rust workspace 与 RuntimeAdapter 骨架。
