系统不变量与证据边界

v0.5 将 ResourceGroup 与 ResourceAccount、设计与事实、任务候选与唯一提交分离。这里展示的是当前规范和局部原型证据；未完成真实 provider、故障注入、100K Fiber 和分布式验证前，不宣称生产闭合。

Budget 随机性管理 安全与授权 宗旨验证
Economy · 支撑设施/ 01

Budget：失控 agent 是财务事故，不是性能事故

方向修正归位：Budget 是负载无关的计量设施，不是系统灵魂。Unix 进程死循环浪费免费时间片，agent 死循环烧钱。计价单位用抽象 credits：不用 token（不同模型单价不同，不是稳定货币），不用法币（内核不该碰汇率）。驱动回报实际用量，用户态定价表折算，内核只记 credits——内核与价格波动隔离。

内核 · 权威

余额 balance

当前可用量，陷入点原子扣减。

内核 · 热路径

记账流水 ledger

每笔扣减事件：哪次调用、花多少。WAL 批量组提交（议题 11 裂缝 1）。

内核

继承树 inheritance

父子划拨关系，A spawn B spawn C 的问责链。

ELF + 用户态

耗尽行为 exhaustion

归零时挂起 / 降级 / 通知，agent 注册自己的 handler。

用户态

定价表 pricing

各模型 / 工具单价，价格波动隔离在内核之外。

继承

ELF 要价 + 父审批

子 ELF 声明 budget.request，父（或其 Policy）在 spawn 时批准 / 拒绝 / 调整。支持中途回收未用预算。被否决：共享池——一个失控子 agent 抽干全部兄弟。

耗尽

80% 预警 + 默认挂起

80% 阈值信号给优雅收尾窗口（主动 checkpoint、申请增资）；100% 默认 suspend，状态保留、充值可恢复——最诚实的失败。degrade 仅限 ELF 显式声明：隐蔽失败比显式失败更危险。

透支

max_tokens 硬顶（议题 11 拍板）

陷入时余额是预检，实际成本事后才知。内核把剩余预算折算成 max_tokens 随调用下发，驱动物理截断生成——物理保证，无账本复杂性；工具调用用 preauth 预估冻结作补充。

计费

实际成本 + 钉页费 + 发送者预付

钉住页按「页 × 步数」计费，防止 pin-everything 滥用；KV 共享页按驱动回报的实际成本记账，不做二次分摊。消息投递发送者预付——spam 制造者自付成本，真正的经济背压（议题 11 拍板）。

Stochasticity · 支撑设施/ 02

随机性管理：Unix 把故障当异常，agent OS 把故障当统计

内核消灭不了幻觉，只提供测量、隔离、冗余原语。可靠性是用 Budget 购买的商品。agent 故障 = 拜占庭故障：看似健康地输出错误，检测需要语义判断——检测必须先于监督（Erlang 监督树结构照抄，触发器换掉）。

1

变体重试

成本 ~1x · 默认

重试时改变 temperature / 措辞，打破相关性失败——同模型同提示词跑 3 次，大概率犯同一个错。

适用：所有任务默认档
2

校验器

成本 ~1.x 倍

生成-校验不对称：验证常比生成便宜（代码跑测试、数学验算）。确定性校验器最优，LLM 校验器次之。

适用：可机械验证输出的任务
3

N-版本投票

成本 ~3x

3 个多样化实现多数决。冗余必须多样化才有效（不同模型 / 提示词 / harness）——航空软件 N-version programming 先例。

适用：关键步骤（ELF 声明 criticality）
4

检查点回滚

成本 = 存储

检测到错误后 rewind 到出错前。语义难点：哪个 checkpoint 是「出错前」？依赖检测先行。

适用：长任务

无进展检测 · 两级制

agent 空转（livelock）持续烧钱但无语义进展，每步都在「正常」调用，Unix 死循环检测无效。

  1. 内核看门狗：「喂狗」= 新产物写入、新工具调用、任务清单推进、显式心跳。ELF 声明阈值 maxStepsWithoutProgress / maxRepeatSimilarity，到阈值挂起 + 标记
  2. 用户态语义监督：监督 agent 审查 trace，裁决恢复（误报）/ 转向（注入新指令）/ 杀死（从 checkpoint 重启）。内核只看信号不看语义

幻觉传染隔离 · 溯源 + 接触追踪

单 agent 幻觉是 bug，幻觉经消息传给 500 个下游是疫情。共享通道上的每条信息内核强制携带溯源元数据：

来源 agent lineage 推导链 断言级别（事实 / 结论 / 推测） 验证状态（verified / unverified）

与污点追踪对偶，合起来是完整信息血缘图。「规划上下文只许 verified 进入」是可强制规则；某 agent 判定幻觉后沿 lineage 前向追踪污染，git 版本化 Blackboard 支持定位回滚。血缘数据有 GC：lineage TTL + 分层归档（议题 11 裂缝 4）。

Security & Consistency · 支撑设施/ 03

权限只能衰减，签字分三级

自我修改触及 requiresReauth 段（工具 / 权限声明变更）时，谁签字？衰减原则结构性地回答了这个问题：委托只能衰减，不能放大——于是内核可以做纯集合包含的机械校验，而扩权请求物理上无法被父批准，只能沿授权链上行。

L0

内核机械校验

一切重授权 · 同步必过

请求的能力 ⊆ 父的当前信封？纯集合包含判断，零语义——完美符合「内核从不信任，只设界」。

签字人：内核（不变量）
L1

常备授权

信封内低风险变更 · 即时

Policy 守护进程按预批规则自动签（polkit / OPA 类比）。绝大多数重授权是规则可预见的——规则就是「预先签好的字」，人类只见例外。这回答了「人类是瓶颈」的反对。

签字人：组织 Policy 守护进程
L2

上行扩权

超出父信封 · 阻塞等待

父签不出自己没有的能力，扩权沿链上行至信封源头——最终必达组织根（人类 / 根 Policy）。等待期 v1 续跑 + 批准后原子热切换（蓝绿部署类比，服务不中断）。

签字人：信封源头 · 人类

一致性参照 OS 模型 · 内核不管信念

「语义一致性」不作为系统层概念——两个 agent 持有矛盾信念在 agent 社会里是常态甚至资产，强制统一 = 群体思维。内核的边界：

  1. 系统状态一致性：内核保证共享信息空间（串行化锚点 + 分片 + 分档保证，类比 O_SYNC / 缓冲写的档位）
  2. 进程私有状态：内核只管 checkpoint / restore 自身完整性
  3. 信念协调：非系统层——内核提供同步原语（黑板锁 / 消息有序 / provenance），裁决归用户态组织层。分歧可见、可追溯、可裁决，但不统一

控制面防注入 · 内核级强制

agent OS 独有的新攻击面：控制面里的 LLM（调度 / 监督 agent）要读 agent 的产物才能做语义决策，恶意 agent 可以在自己的 trace 里埋注入指令。

定案：控制面 LLM 输入全污点化、只允许结构化数据、原始 trace 永不进指令通道——立为内核级强制规则。控制 = 设界，不是理解：OS 不需要理解程序就能杀死它。provenance 强制携带不是可观测性设计，是控制权的根基。

克隆群体的记忆一致性：不可变 base + overlay。100 个实例从同一 seed 分叉后各自漂移，组织更新基础知识 = 发布新 base 层版本（只读共享），实例本地写在 overlay；rebase 仅当实例写过同 key 才冲突——git 双向合并的万级冲突地狱被结构性绕过。这与 OCI 分层镜像、KV 前缀共享是同一个分层思想的三层合流。

Validation/ 04

为什么能成：六大死因，逐一回查

诚实的边界：内核保证「万级可存活」，不保证「万级有产出」。本设计解决规模生存问题——不死、不爆、不烧穿预算、不传染；万级 agent 能否协调出有效产出是组织设计问题（部门 / 角色 / SOP），属于 ELF 与用户态层。正如 Linux 让你能跑一万个进程，但它们是否构成有用系统取决于应用。边界清晰，且必须在定位上说破。
