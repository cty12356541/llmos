陷入如何不可绕过

ring 保护的软件等价物：凭证托管——agent 拿不到原始模型 API key，模型端点只接受内核签名的请求；网络策略——沙箱网络规则使工具只能经内核网关到达。不是靠硬件特权级，靠凭证加网络隔离。

为什么是微内核

经典微内核（Mach）死于 IPC 性能开销。agent OS 里这个死因不存在：LLM 调用延迟 100ms–10s，IPC 开销微秒到毫秒——IPC 税相对系统调用延迟是噪声。Mach 是对的思路错的基座，agent 给了它对基座。

不站队两大阵营

harness/沙箱派与图编排派共用 MCP + A2A 协议底座。harness 程序和图编排器都是 NLOS 内核之上的用户态程序——内核在两者之下，这就是桥。私有草稿不陷入，对应进程访问私有内存不陷入。

Abstractions/ 02

对象必须分离：应用、执行、数据、资源与设备

v0.5 不再让 Agent 一词同时承担应用、包、身份和进程。完整层级是 Application → Process → AgentInstance → ExecutionFiber/Activation；Task 是持久义务，Artifact 是数据本体，Context 是派生工作集，ResourceGroup 与 ResourceAccount 分别负责物理隔离和账本归属。

Agent计算族 · Unix: 进程

可调度执行单元。通用进程抽象：LLM 能力是一种可选 handle——纯代码 worker 与 LLM agent 同一抽象，拒绝第二种进程类型（议题 13）。调度粒度 = 一个推理步（计量模型下 = chunk 边界）。

内核　生命周期状态机 · 步边界陷入 · 身份（ID / 父系 / 版本号）

Context内存族 · Unix: 虚拟内存

上下文窗口 = 物理内存；RAG = 请求调页；embedding 索引 = 页表；压缩 = swap；KV 前缀共享 = 共享库。映射最精确的一块。

内核　页记账 · 钉住强制（mlock）· 换页执行 · KV 共享机制

Tool设备族 · Unix: 文件/设备

外部能力入口。MCP 就是 /dev。双设备类：MCP（结构化，RPC 语义）+ shell/文件（字节流），内核不选边。

内核　工具调用陷入 · 能力校验（handle）· 沙箱强制挂钩

Message通信族 · Unix: 管道

定向、有序、消耗品的消息流，并发语义为背压——写满阻塞写方，且必须与调度原子。投递计费：发送者预付（议题 11）。

内核　投递保证与排序 · 背压阻塞 · 寻址路由

Topic通信族 · Unix: 无（新发明）

群发、有序、消耗品的广播主题，并发语义为兴趣过滤——万级规模解决 O(n²) 洪水的核心机制。过滤器 = eBPF 先例：执行不理解。

内核　投递与排序 · 路由 · 过滤谓词的安全执行

Blackboard通信族 · Unix: 共享内存

共享、持久的状态区，并发语义为 git 式合并。定案：内核元数据 + 用户态字节（inode 缓存 vs 磁盘字节）。

内核　handle / 版本序号 · 写串行化 · wakeup 原子性 · 污点

Budget经济族 · Unix: 无（新大陆）

一切行动折算统一货币消耗，陷入点原子扣减，耗尽强制执行。负载无关的计量设施——治理语义归用户态可插拔模块。

内核　扣减核算 · 耗尽强制 · 继承树权威记账

Policy安全族 · Unix: 用户/权限

权限、Namespace、generation 与版本门控。Capability 类似不可伪造 handle；发现、命名和授权必须分离。

内核　陷入点强制校验 · 污点传播 · 版本门控 · 衰减机械校验

调度器不进内核热路径。算术否决了 LLM 上热路径：万级 agent × 每步约 2s = 每秒数千调度事件，LLM 决策追不上。分层调度：内核 dispatcher 纯算术，零智能；用户态调度 agent 是 sysctl writer，慢循环写参数进内核（/proc/sys 类比）。内核强制不变量（预算守恒、公平性下界），dead-man's switch 兜底。

Syscalls/ 03

27-entry KABI candidate，先纵切面验证再冻结

v0.5 当前是 27-entry KABI candidate：Process、对象映射、Namespace/Handle、generic async I/O、Resource 与可信计量。数量尚未冻结；Topic、Blackboard、Package、Semantic 与桌面属于稳定系统服务，不应被硬塞进微内核。

Executable Format/ 04

ELF：不是文件格式，是三方契约

v0.5 将 Package、Installation、Application、Executable 与 Process 分离。Package 是不可变签名制品，Application 是安装、授权、更新和用户数据归属单位；MCP、A2A、浏览器和本地 CLI 都只是可替换 Driver adapter，不能成为系统身份。

researcher.agent.yaml — manifest 示例 
apiVersion: nlos/v1alpha2
kind: Agent
metadata:
  name: researcher
  version: 1.2.0
  digest: sha256:...
  signature: <开发者签名>
spec:
  runtime:                    # ABI 声明
    loop: react
    model: { minTier: 2, preferred: [...] }  # 可选：纯代码 worker 无 LLM 手柄
  instructions:
    core: ./instructions.md   # 只读段（text segment）
  skills:
    - path: ./skills/web-research/
      mutable: true           # 允许自我修改的段
  tools:                      # 动态链接（NEEDED）
    - mcp://.../web-search@^2.0
  memory:
    layout: memfs
    seed: ./memory/seed/      # 记忆烘焙
    quota: 100k
  budget:
    request: 50k/day
    exhaustion: degrade       # suspend | degrade | notify
  permissions:                # namespace 绑定请求清单（安装时授权）
    blackboards: [research-shared]
    topics: { subscribe: [news.*], publish: [findings] }
  interfaces:                 # 符号表：内嵌 A2A Agent Card
    skills: [deep-research]
  selfModification:           # 段可变性声明（格式级）
    allowed: [memory, skills]
    forbidden: [instructions.core]
    requiresReauth: [tools, permissions]
  lifecycle:
    restart: on-failure

加载流程 · spawn 时内核做什么

  1. 验签 + digest 校验（Policy）
  2. 权限请求 vs 组织 Policy 比对（超权拒绝或降权）
  3. 双划拨：预算切片 + 按 permissions ∩ 父信封构造子 namespace
  4. 记忆 seed 加载 + COW 层建立（Context）
  5. 工具依赖解析（绑定 handle = 动态链接）
  6. 注册接口（A2A card 发布到发现服务）
  7. 进入调度队列，从 entry 开始第一步

记忆烘焙与 lineage 身份

包内含 seed 记忆 = 经验分发；100 个实例共享初始记忆后各自分叉（COW）。副本 = 同一 lineage 的新实例，授权随 lineage 链验证。工具 + 权限声明的修改必须重授权（requiresReauth）——运行时走三级签字链（衰减 + 常备授权 + 上行，议题 10，见支撑与验证）。

Universality/ 05

通用性不是口号，是可检验的判据

方向修正后的主线第一题：设计通用系统。判据取自 Unix 通用性的来源；裁判标准是重构测试——能否用 NLOS 的原语把现有计算模式全部重构为用户态程序。压测结果：能。

01

抽象正交性

抽象各自独立、任意组合。通用性不来自抽象数量，来自组合自由度——LangGraph 编排器 spawn CrewAI 团队内含 Letta 记忆 agent，正交组合成立。

02

对负载的无知性

内核不知道也不关心程序在算什么。它只知道能力集合、预算余额、步数、污点、路由地址——结构信号，不是语义判断；Topic 谓词「执行不理解」。

03

可组合性优先于功能

pipe 没有「功能」，但让一切功能可组合。内核提供原语，模式在用户态组装。

04

机制下限，生态上限

系统提供最少机制，通用性由生态组合涌现。MVS 是反面：功能内置，越全越专用。

裂缝 A 修复 · 计量流陷阱

流式 / realtime 模型是持续流，不是请求-响应的「步」——步边界抢占对流失效。修复：流 = 一个保持打开的长陷阱，驱动按 chunk 增量回报用量，内核增量扣减预算，额度耗尽掐断流；抢占点从步边界推广为 chunk 边界。

步模型不破，推广为计量模型：请求-响应 = chunk = 1 的特例。max_tokens 硬顶同步推广为「累计计量上限」。

裂缝 B 修复 · Process 与 AgentRole/AgentInstance 分离

纯代码 worker 不应被迫伪装成 Agent，也不应被迫调用 LLM。Process 是宿主强制执行的资源、故障和生命周期单位；AgentRole 是语义角色，AgentInstance 是 thread/actor-like 执行身份，LLM 只是可选 Device capability。

通用性的代价可负担：不变量（能力 + 预算）永不旁路；陷阱成本相对 LLM 延迟是噪声，通用性买得起。
