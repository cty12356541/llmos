v0.5 §5.1 微内核五项驻留测试

任一机制必须同时通过以下五项判据方可进入微内核 TCB，否则留驻 SABI 系统服务（[KERN-BOUND-001]）：

  1. 不可绕过强制：一旦旁路即破坏隔离、能力执行、资源守恒或生命周期正确性；
  2. 状态迁移原子性：必须与权威账本、纪元围栏或句柄状态原子提交；
  3. 零自然语言理解：完全不解析 Prompt、业务意图或语义内容；
  4. 负载与协议中立：独立于特定 LLM、Provider、MCP/A2A 协议与应用形态；
  5. 原语最小不可约：无法由更小的内核原语在用户态无损组合实现。

四重名义身份彻底解耦

Package ≠ Installation ≠ Application ≠ Process：Package 是由哈希与签名锁死的静态分发包；Installation 记录工作区授权与当前激活版本；Application 持有长期身份与用户资产归属；Process 仅代表某次具体运行实例。

Package（只读签名层）WASM / 二进制 · 静态模板
Installation（授权绑定层）衰减 Capability · SABI 协商
UserDataContainer（用户数据层）跨升级/回滚持久保留

UserDataContainer 升级与回滚保护

应用升级或回滚只切换 Installation 指向的不可变 Package 版本与显式 schema 迁移器，绝不原地覆写或清空 UserDataContainer。正在执行的已冻结 TaskAttempt 继续引用启动时的包修订切面（[PHIL-MATRIX-001]），杜绝升级半途静默篡改运行语义。

安装与 BirthDecision 七步门控

  1. 校验 content_digest 与发布者 Ed25519 签名链；
  2. 协商 sabi_target = "v1-beta" 与必需系统服务特性；
  3. 经可信 UI Z4 或工作区策略裁剪并签发衰减 Capability；
  4. 绑定或创建隔离 UserDataContainer，隔离代码段与用户状态；
  5. 启动时对 ResourceAccount 同质信用预留（[BUD-ALG-001]）、ResourceGroup 多维配额（[RSM-ALG-001]）与私有 Namespace 执行 prepare；
  6. 持久化写入原子 BirthDecision = COMMIT 并分配 generation；
  7. 拉起 OS Process + Wasmtime 双层沙箱进入受控调度队列。
Universality & Slice K/ 05

16 类工作流重构判据与 Slice K 端到端闭环实证

通用操作系统的最终验收问题是：设计者事先未预见的第三方应用能否在不修改微内核的前提下安全安装、运行与审计（[NLOS-GEN-001]）。我们以四项通用性判据重构 16 类主流范式，并在 Stage B/C Slice K 纵切面完成实机闭环验证。

01

抽象正交可组合

执行、能力、数据、资源与通信彼此正交。状态图编排器可在同一 TaskGroup 内派生多角色团队并调用纯代码 Worker，无需内核新增胶水特例。

02

内核对业务语义无知

微内核只裁决 Capability 位图、ResourceAccount 同质信用守恒余额（[BUD-ALG-001]）、generation 围栏与 I/O 背压，不解析任何自然语言或领域规则。

03

机制下沉，模式留在用户态

ReAct、群聊辩论、层级委派或持久工作流均为用户态库或 TaskPlan 拓扑，内核只守住不可绕过的跨边界原语。

04

单套进程模型兼容全部负载

纯确定性 Rust/WASM 计算节点与高频调用模型的 AgentInstance 共享同一套 Process 隔离、资源配额与回执基础设施。
