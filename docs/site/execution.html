Execution Hierarchy/ 01

从用户应用到一次最小执行片段

传统系统是 Application ⊇ Process ⊇ Thread ⊇ Coroutine。NLOS 保留这一成熟分层，但把 Agent 的身份、语义和异步外部操作显式分开。

APPLICATION

Application

用户可见功能、安装、授权、更新和数据所有权整体；可拥有多个 Process 与长期后台 Task。

RESOURCE / FAILURE BOUNDARY

Process / IsolationUnit

宿主可抢占的资源、生命周期、故障与强隔离边界；不要求与 OS PID 一一对应。

THREAD / ACTOR-LIKE IDENTITY

AgentInstance

AgentRole 在特定 TaskAttempt 与 Process incarnation 中的一次可调度身份；不是安全边界。

COROUTINE / FIBER

ExecutionFiber

可挂起、恢复的用户态执行流，在有限宿主线程与 event loop 上 M:N 复用。

DISPATCH QUANTUM

Activation

一次实际获得执行权的 turn，用于调度、追踪和 CPU/model/tool wait 分维计量。

Operation 不是 Fiber。

Operation 是一次 future/异步 I/O/模型或工具调用，拥有独立 deadline、cancel、幂等和副作用状态；调用者消失后，外部效果仍可能需要 reconcile。

应用自己调用依赖

像 Windows/macOS 应用使用系统服务一样，Application 通过 ServiceDirectory、SABI 与 Capability 解析模型、工具、Artifact、搜索、通知和设备，不需要用户手工逐层指挥。

用户仍保留最终控制

计划可预览、编辑、冻结 revision 或重新授权。自动 Planner 只能在授权 Namespace、ResourceContract 和 policy 内行动。

PID-scale Logical Execution/ 03

管理 PID 级逻辑实体，不是同时运行十万个模型

规模来自逻辑对象持久化、惰性物化、Context 工作集和分层调度。系统必须持续公开以下五个互不等价的数字。

LOGICALTaskNode

计划中存在，只占有界 metadata。

MATERIALIZEDInstance

已有 Attempt、Process 或 AgentInstance。

RUNNABLEFiber

依赖和资源满足，等待 runtime dispatch。

ACTIVESlot

正在消耗 CPU、GPU、模型或 Driver 槽位。

RESIDENTWorking Set

占用内存、KV cache 或 pinned Context。

G

Global Scheduler

Tenant/Workspace/Application fairness、Cell placement 和全局 quota；不参与每个 token 的热路径。

C

Cell Scheduler

TaskAuthority、本地 capacity、bulkhead、TaskGroup queue 和跨 Worker placement。

W

Worker Runtime

Process/Agent/Fiber runnable queue、work stealing、context affinity、batch 和本地 backpressure。

GLOBAL CONTROLWorkspace / Application policy · global admission

全局只做 placement、quota 与公平策略，不扫描每个 Fiber。

CELL CPlacement / recovery

WORKER 01Process queues

WORKER 02Agent queues

WORKER 03Fiber runtime

Consistency & Isolation/ 04

控制得住，不等于让所有 Agent想法完全一样

NLOS 管理的是可验证的共享状态与提交协议，而不是强迫概率模型拥有全局统一信念。

TaskSnapshot

每个 Attempt 从 causal-closed、不可变输入切面开始，避免执行中读取悄悄漂移。

独立 Attempt

retry、hedge 和 refinement 使用不同 TaskAttemptId、generation、Capability 与 staging area。

唯一 canonical commit

多个候选可以并行产生，只有获得 CommitPermit 并赢得 TaskHead CAS 的 Attempt 能成为 canonical 结果。

EffectPermit 与未知态

副作用按 slot/幂等身份 fencing。无法证明外部效果停止时进入 PARTIAL_EFFECT 或 EFFECT_UNKNOWN，不能改名为失败前取消。

IsolationDomain

Namespace、Capability、ResourceGroup、Snapshot、Channel、secret、network/device、cancel 和 failure domain 共同构成隔离面。

ControlDomain 独立性

共识和 quorum 按独立控制域计数；复制多个同源 Agent 不能伪造认识论独立。
