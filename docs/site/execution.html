Execution Hierarchy/ 01

从应用归属到单次调度回合：五层包含执行模型

继承现代操作系统 Application ⊇ Process ⊇ Thread ⊇ Coroutine 的成熟演进规律，NLOS（议题 29 · v0.5 §3.2 / §8 · [MODEL-EXEC-HIER-001]）将安全隔离边界、智能体角色身份、用户态控制流与分维计量回合显式拆分为五层包含关系。

01 · APPLICATION

Application

安装、授权、版本升级与隔离 UserDataContainer 数据所有权主体；可同时拥有多个受控 Process 与跨会话后台 Task。

02 · ISOLATION UNIT

Process / IsolationUnit

宿主强制抢占的内存、FD、网络与崩溃隔离边界（OS 进程 + Wasmtime 双层沙箱）；互不信任的执行必须分属不同 Process。

03 · ACTOR IDENTITY

AgentInstance

AgentRole 在特定 TaskAttempt 与 Process 纪元内的一次可调度认知身份，绑定 ControlDomain，本身不冒充硬件安全边界。

04 · COROUTINE FLOW

ExecutionFiber

在有限宿主线程与事件循环上 M:N 复用的轻量级用户态协程；I/O 或模型等待期间零宿主线程占用，隶属结构化并发取消树。

05 · METERING TURN

Activation

ExecutionFiber 实际获得调度权或跨出边界的最小计量片段；每次外部交互穿过显式 Activation 门控，重调度生成新记录绝不覆写旧账。

[MODEL-ACTIVATION-001] / [FIBER-METER-001] · Turn Boundary 6 Metering Dimensions

6 维 Activation 显式分相计量边界

每一次调度与跨边界等待必须穿过类型化 Activation 边界，区分 6 类运行与等待时间并归集至 Fiber → AgentInstance → Process → TaskAttempt/TaskGroup → Application/Workspace 层级 ResourceGroup（[RSM-ALG-001]；同质信用费用独立经 ResourceAccount 守恒结算 [BUD-ALG-001]）：

active CPU · 实际宿主计算 model wait · 模型推理/流等待 tool/I/O wait · 工具与异步 I/O 等待 scheduler wait · 队列就绪等待 blocked-on-backpressure · 发送背压阻塞 suspended time · 静止点挂起时长
ADR-0009 / ADR-0012 · nlos-runtime + nlos-runtime-tokio PARTIAL_PASS H3/H6

事件溯源协程重放：拒绝脆弱的 WASM 原始栈内存转储

跨编译器升级或宿主迁移时，原始 WASM 线性内存栈快照（raw stack dump）极易因布局偏移而失效。nlos-runtime 与 nlos-runtime-tokio 将确定性协程事件日志与阶段快照持久化至 SQLite，在恢复或接管时沿 Activation 检查点精确重放控制流，并配合 OperationId 幂等去重阻断外部副作用重放。

Operation 不是 ExecutionFiber。

ExecutionFiber 是进程内控制流；Operation（[MODEL-OP-001]）是一次携带独立单调截止期、取消纪元、IdempotencyKey 与副作用状态的异步外部操作。即使发起调用的协程或进程崩溃退出，在途 Operation 仍由系统追踪并对账结算。

[PLAN-UNTRUSTED-001] · 规划器输出零信任校验

无论 TaskPlan 来自前沿大模型、应用内置模板（ADR-0016）还是外部导入，nlos-plan 均将其视为不可信候选输入：在进入调度器前同步执行 Schema 结构检验、拓扑无环证明、TaskWriteSet 冲突预检、Capability 范围核验、ResourceGroup 多维配额核定（[RSM-ALG-001]）与 ResourceAccount 同质信用预留（[BUD-ALG-001]），并与锁死 proposal_digest 的 AuthorizationReceipt 绑定。

[PLAN-CHANGE-001] / [PLAN-OVERRIDE-001] · 自动与手动改图同门控

Snapshot & Dual-Permit Fencing/ 04

并发候选不乱序：不可变快照、六域冲突代数与双许可围栏

多智能体并行探索、超时重试或投机执行（hedging）是常态，但权威状态绝不允许“最后写入者静默覆盖”。v0.5 以因果闭合 TaskSnapshot 为起点，用六域冲突代数与 CommitPermit / EffectPermit 双许可协议守住内外一致性。

TaskAttempt A（Winner）

CANONICAL COMMIT

基于只读 TaskSnapshot (rev N) 独立执行，率先通过冲突检测并赢得任务头原子交换。

01 · READ IMMUTABLE TaskSnapshot (rev N) 02 · STAGE OUTPUTS & VERIFY 6-DOMAIN WriteSet 03 · ACQUIRE CommitPermit (CAS rev N → N+1) 04 · PROMOTE CANONICAL + SEAL ControlReceipt
DUAL-PERMIT LINEARIZATION

TaskHead CAS & Effect Fence

内部状态靠 CommitPermit 保证单代唯一赢家；外部世界靠 EffectPermit 携带代际与幂等键精确围栏。

TaskAttempt B（Fenced / Uncertain）

EFFECT_UNKNOWN + QUARANTINED

落后竞争者被确定性中止归档；若外部驱动超时失联，立即隔离冻结，严禁盲目自动重试。

01 · READ IMMUTABLE TaskSnapshot (rev N) 02 · INTERNAL CAS LOST → ABORT & RETAIN AS EVIDENCE 03 · EXTERNAL TIMEOUT WITH EffectPermit(gen, idem_key) 04 · ENTER EFFECT_UNKNOWN + QUARANTINED (NO BLIND RETRY)
ADR-0013 / ADR-0017 · Conflict Algebra 6 WriteSet Domains

六域 TaskWriteSet 确定性冲突代数

每个 TaskAttempt 在提交前必须对其声明与实际触达的六个权威状态域执行读写/写写冲突判定，任何未声明越界写入直接拒绝：

TaskHead · 任务权威头指针 ArtifactNamespace · CAS 命名空间路径 BlackboardKey · 共享状态键值修订 SemanticAssertion · 语义断言主题 ResourceAccount · 同质信用守恒结算 ExternalDevice · 排他设备与外部槽位
External Side-Effect Safety · nlos-operation + nlos-driver-mock QUARANTINED Fence

CommitPermit 与 EffectPermit 内外双围栏

内部状态（CommitPermit）：通过原子 TaskHead generation CAS（rev N → N+1）确保同一义务代际至多一个赢家，失败候选转为只读 Evidence。
外部副作用（EffectPermit）：向受管驱动与操作围栏面（nlos-operation + nlos-driver-mock / nlos-provider-worker）传递 (task_id, attempt_id, generation, idempotency_key)；一旦崩溃或网络超时令外部结果未知，状态机强制进入 EFFECT_UNKNOWN + QUARANTINED，严禁盲目自动重试，直至幂等查询或人工对账收口。

10-Layer Manual Control/ 05

十层精细干预与四面字节等价回执

顶层自然语言自动化绝不剥夺用户的底层掌控权。v0.5 §25.3 将系统从全局主机一直到单次设备异步操作拆解为十个可观察、可授权干预的控制层级，并强制所有交互入口收敛至同一条权威执行链。

01 · System 全局负载水位、资源压力等级、性能/离线模式、TCB 清单健康度与紧急全局冻结
02 · Workspace 多用户/组织命名空间隔离边界、跨域共享策略、总预算配额上限与审计保留窗口
03 · Application 签名应用启动、激活、后台挂起、卸载回滚、网络/设备授权与 UserDataContainer 配额
04 · Task 16 态持久义务检视、暂停、恢复、取消、截止期重设、预算追加与人工接管（Takeover）

07 · Process / Agent / Fiber 双层沙箱审查、排空/取消/冻结挂起（Drain/Cancel/Freeze）、强杀、核亲和与协程事件重放
08 · ResourceGroup / Context 多维容量/速率/配额（[RSM-ALG-001]）requested / effective 水位、驻留工作集 pin、节流与 reclaim / evict（与 ResourceAccount 同质信用守恒账本 [BUD-ALG-001] 严格分离）

[CTRL-PARITY-001] · SystemControl v1.6 Byte-Equal Receipt · p50 = 84µs

四面同源编译：字节级完全一致的 receipt_hex

NL Shell、Trusted GUI (desktop)、system-control-cli 与 Structured SABI API 四个交互表面不存在任何“GUI 私有后门”——全部编译为完全相同的 SystemControl v1.6（20 个类型化命令分支），经 ADR-0011 挑战-响应认证本地 IPC 执行统一能力核验与纪元 CAS，产出字节级一致（byte-identical）的 receipt_hex，实测本地控制往返延迟中位数仅 p50 = 84µs。
