Private Namespace · Plan 9 Heritage · nlos-capability & nlos-operation/ 01

私有命名空间：不可命名即不可寻址，句柄跨 Cell 位置透明

继承 Plan 9 每进程私有 Namespace 思想，NLOS 将对象发现与能力授权显式解耦。每个 Process 启动时仅挂载应用清单与父级能力信封交集内的受控 Handle（nlos-capability、nlos-operation、nlos-driver-mock），让进程诞生在一个恰好与其授权边界等大的可寻址世界里。

does-not-exist > permission-denied

未挂载对象在当前私有 Namespace 中根本无法解析为合法 Handle，不泄露宿主目录或邻近租户对象的存在性；与此同时，真正的安全执行边界仍由 Ed25519 能力验签、密钥引用托管与引用监控器出口门禁同步强制。

错误语义：does-not-exist 消除拓扑侧信道

spawn 阶段按签名权限请求与父进程当前能力信封求交集，静态构造子进程私有绑定表。越界名称直接返回未绑定错误，避免像传统全局路径空间那样通过“拒绝访问”暴露敏感服务或文件的存在；运行期临时授权则经 Stage D ADR-0025 (W68-R1/R2) Z4 实心 UAC/Polkit 级安全确认屏与 ChooserGrant 动态注入最小作用域句柄。

Handle 间接寻址：本地与远端 Cell 位置透明

用户态持有的永远是绑定代际（generation）与权限摘要的间接 Handle，而非裸宿主路径、进程 PID 或物理节点地址。当任务跨本地与远端 Cell 路由或迁移时，nlos-operation、nlos-service-directory 与 CellDirectory 在底层重绑端点，名字保持不变，同时忠实保留远程调用的超时、预留结算与污点标记。

为什么 SABI 冻结而外部协议可替换

nlos-schema 注册 8 条 SABI 通道（7 条 v1-beta 已冻结含 ADR-0024 DriverProvider v1.0 + PrincipalHandshake v1.0 未冻结）并以确定性 CBOR 生成 Ed25519 签名原像，保证跨语言 SDK 与守护进程升级零歧义；而 MCP 与 A2A 作为外围适配器挂载在 nlos-operation 与 nlos-driver-mock 驱动边界外，外部生态更替永远不会动摇内核 ABI。

边界适配器绝不拥有内核身份

经由 MCP 或 A2A 返回的数据一律被视为异域非信任输入：引用监控器强制附加外部污点、绑定 Reservation 成本上限与四态 RemoteCallOutcome，杜绝外部服务反向劫持本地控制面。

跨组织清算诚实延后（NLOS-DEFER-001）

v0.5 §29.2 明确将跨组织清算所与全球联邦列为保留接口的延后特性（STAGE E）。当前已取证范围严格限定为同一主权域内的多 Cell 租约对账，不虚构跨组织金融结算。

Elasticity & Backpressure · C-SCHED & C-FANOUT/ 04

弹性、背压与舱壁：信用流控与三层 DRR 工作窃取

四域舱壁与优雅降级

4-Domain BulkheadRegistry

按 Tenant / Workspace / TaskGroup / Provider 四维独立设定容量舱壁并锁定不可侵占的 SafetyTcbSystemReserve；Provider 限流或中断时按签名回退链降档、走缓存或安全挂起。

机制：DIST-BULKHEAD-001

多租户三根隔离与物理封顶

每个租户对应独立的身份授权树、ResourceGroup 容量树与 ResourceAccount 账本树根节点。隔离与预算上限在根部物理闭合：吵闹邻居既无法窥探其他租户命名空间，也无法抢占系统救援保留池或引发超额账单冲击。

Provider 速率限制与宕机下的确定性退化

外部模型限流、高延迟或独立 nlos-provider-worker（nlos-driver-mock 跨进程二进制）子进程崩溃会被转化为类型化 PressureEvent：仅当 ResourceContract 预先授权时才切换备用模型档位或 ProviderCache，否则进入 WAITING_RESOURCE 保全检查点，绝不静默劣化结果语义。

Commandments · Non-Negotiable Engineering Discipline/ 06

不可妥协的四条系统工程戒律

决定 NLOS 是通用现代操作系统而非脆弱 Agent 编排框架的四条底层铁律，贯穿全部 35 个 Rust Crates 与 26 份架构决策记录。

01

机制入核，策略归还用户态

入核唯一判据：若该逻辑被绕过，身份隔离、账本守恒或持久权威是否立即失效？是否必须在陷入点原子完成？两问皆是才进入 TCB；提示词编排、模型路由、角色组织与计费单价一律留在用户态。

02

原语少而正交，总线先验冻结

警惕 Multics 膨胀陷阱：不发明绑定特定业务工作流的特权原语，以最小正交内核对象、SABI v1-beta 冻结通道与跨权威 verify-then-commit（ADR-0013）支撑未预见的第三方应用生态。

03

内核绝不信任推理，只强制物理不变量

Policy is advisory; invariants are physics. 自然语言与大模型只能产出类型化提议；集合包含衰减、ResourceAccount 封闭域守恒、代际 CAS 唯一晋升与租约围栏由确定性 Rust 代码同步裁决。

04

能力声明严守证据上界（Claim ≤ Evidence）

规范条款（DESIGN）、候选架构（CANDIDATE）、故障注入局部闭环（PARTIAL_PASS H3–H6）与生产运行事实严格分级记账；未获对应等级实测证据前，禁止任何跨级宣传。

Semantic Stream & Eight Primitives · nlos-artifact / nlos-semantic / nlos-task / nlos-resource/ 07

语义事件流、八原语闭环与多控制器资源平面

在底层多资源控制器的代数约束下，nlos-artifact、nlos-semantic、nlos-task 与 nlos-resource 协同驱动高层认知任务的完整生命周期：每条认知原子沿只追加验真—墓碑轨迹演进，每次任务循环由八个正交原语闭环组合并按驻留水位有序回收。

CRATE ALIGNMENT · CONTEXT / SEMANTIC / RESOURCE

原语环与三平面权威 Crate 对齐

八原语并非松散的业务工作流提示词，而是逐项映射到受内核计量与驻留策略管控的系统原语：

  1. 摄取与分解（Acquire / Decompose）：由 nlos-operation 与 nlos-driver-mock 带污点摄入外部输入，经 nlos-plan 编译为受准入审查的有向无环 TaskPlan。
  2. 投递与推演（Transmit / Generate）：经 nlos-topic 单日志有界扇出投递，在 nlos-runtime + nlos-runtime-tokio 与 nlos-resource 预留门控下执行推理步。
  3. 验真、关联与归约（Verify / Relate / Aggregate）：由 nlos-semantic 建立签名血缘边并物化 AuthorityView，经 DeterministicLocalReducer 生成 Merkle 结果根。
  4. 受控驱逐（Forget）：由 nlos-artifact、nlos-semantic 与 nlos-task 按工作集水位回收 RECLAIMABLE 缓存并冻结检查点，保持十万级逻辑任务的极低常驻内存开销。
