现代系统：通用内核之上

通用性定案之后，主线第二步：namespace 收敛全部权限语义，蜂窝拓扑解决分布式，协议栈保持可替换，弹性多租户与分层可观测性收官——新抽象不增加概念，反而收敛旧概念。

namespace 分布式内核 协议栈 弹性多租户 可观测性 设计原则
Namespace · 现代系统 1/5/ 01

命名即权限——agent 诞生在一个恰好和权限一样大的世界

Plan 9 遗产：每进程私有名字空间，绑定即能力。namespace 不新增抽象，是能力表的泛化；七项已定决策在它之下收敛——好架构的标志：新抽象不增加概念，反而收敛旧概念。

不可命名 = 不可想象

namespace 的内容会被投射进 agent 的上下文窗口——工具列表就是它的世界观。面对注入指令「访问这个 URL」，namespace 里没有网络工具的 agent 失败的原因不是调用被拦截，而是它根本不知道这件事可做。防御从拦截行为前移为限制想象——提示注入防御的最深一层，比污点、比 Policy 校验都靠前。

错误模型：does-not-exist，而非 permission-denied

spawn 时内核按 ELF permissions ∩ 父信封静态构造子 namespace。agent 永远不会对界外事物得到「拒绝访问」——那些事物对它不存在。

信息隐藏强度对比：permission-denied 泄露「东西存在但你不能碰」；does-not-exist 什么都不泄露。运行期变更走常备重授权通道（议题 10 L1），边界清晰可审计。

七项旧决策在此收敛

能力表 = namespace 绑定表 衰减 = 子 namespace ⊆ 父 spawn = 构造子 namespace 污点 = 标记区（/untrusted/*） ELF permissions = 绑定请求清单 工具注册中心 = 设备仓库 控制面只有结构化输入源可命名

外部资源（A2A / 远程）与本地同一 namespace，绑定在污点标记区——位置透明 + 信任可见。

为后续议题铺路的红利。/proc 类比：内核统计与 agent 状态作为只读名字绑定（/sys/agents/*）——可观测性的形状（见本页可观测性）。import：把远程资源绑进本地名字空间，位置透明从 namespace 间接性免费得来——分布式与联邦的地基。

Distributed Kernel · 现代系统 2/5/ 02

蜂窝式内核：本地数据面 + 集中控制面

先算账：跨机陷阱的额外延迟（LAN 0.5ms / 跨机房 50ms）相对 LLM 调用仍是噪声，集中式「算得过来」——但可用性与 10k 以上扩展是算术解决不了的问题。答案是被 service mesh（Envoy + Istio）与 Kubernetes（kubelet + 控制面）在万级规模验证过的拓扑；现代系统 4/5（service mesh 同构）的核心内容即此，不单立。

红利一 · 优雅降级

控制面宕机，系统靠未到期的租约滑行：运行中的 agent 不受影响，只是不能 spawn / 迁移。DHCP 租约、Kerberos 票据同款设计。

红利二 · 故障域自动封闭

父 agent / 节点死亡 → 子的份额到期自动耗尽 → 自动挂起。没有孤儿失控 agent——TTL 就是自动收容所。

红利三 · 迁移账本不动

账本权威在控制面，永远不「搬」：迁移 = 归还源节点份额 + 目标节点发新份额。透支上界 = 份额大小，max_tokens 硬顶在分布式下完整保留。

迁移语义 · drain 优先

默认 drain：等到步边界（在途调用完成并结算）再迁，与协作式调度模型一致。紧急 evacuate（节点将死）：取消传播掐断在途调用，按实际发生结算记损耗，立即迁。

namespace 重绑定：名称稳定、端点可变——目标机注册表把同一名称解析到本地端点（位置透明，namespace 的红利）。机器专属资源用 pinned 绑定（K8s node-affinity 类比）：要么禁止迁移，要么迁移后代理回源。

一致性档位 = 分布策略

议题 12 的档位直接就是分布策略：

  1. 强：主副本串行化——每个黑板有 home 节点，写路由到 home 排序；命名空间分片天然负载均衡
  2. 最终：多主 + merge driver——git 式合并模型天然就是多主
  3. 无：本地黑板，不跨机。Raft 仅用于控制面小状态——Raft-per-blackboard 被否
Protocol Stack · 现代系统 3/5/ 03

内核不说 MCP 也不说 A2A——只说名字和绑定

协议的位置不是内核，是栈。内核的一等公民是 namespace 绑定；协议是绑定下面的可替换栈层——协议死了换一个，内核不变。协议演进独立性 = 通用性保全（议题 13 判据：对负载与实现的无知）。支线「MCP vs A2A 协议位置」在此一并关闭。

名字透明 + 语义显式

外部 agent 以本地名字绑进 namespace（位置透明的命名），但绑定类型可见。调用外部绑定产生远程任务：显式超时 / escrow 支付 / 污点结果 / 部分失败状态——不是假装它是一条本地 Message。POSIX 同款智慧：一切都是 fd，但 socket 的 read() 和文件的 read() 返回不同的错误。不欺骗，也不分两个世界。

「分布式计算注记」一半失效

1994 年 Sun 论文的四差异逐项检查：延迟差异淹没在 LLM 延迟里——失效（本地调用秒级 vs 远程秒级 + ms）；部分失败、信任域、结算依然成立——必须显式（外部可中途死亡；远程输出是异组织污点数据；跨组织是真结算）。

跨组织结算 · 清算所净额

B 的 agent 调用 A 的 agent：付 B 的本地 credits，内核只记本地账不变；控制面之间按周期净额轧差（客户各自交易，银行间清算所轧差）。每调用实时 escrow 被否。信任引导：A2A 签名 Agent Card + DID；导出 / 导入 + TTL 租约，吊销 = 解绑。

Elasticity & Tenancy · 现代系统 5/5/ 04

弹性有三个维度，预算是天然刹车

经典云弹性只有一个维度：实例数（HPA）。agent OS 有三个。机制在内核（spawn / suspend / tick / 档位），策略在用户态——弹性策略 agent 是 sysctl writer 家族的新成员，监视结构信号（Topic 队列深度、Message 积压、预算燃烧率 vs 进展）慢循环调参，零新机制。

1

实例数

spawn / suspend / resume

水平扩缩。记忆烘焙让弹性实例带经验上岗：从 ELF 镜像 spawn 新实例 = 带 seed 记忆 + COW——云的 cold start 痛点被化解为「新实例从组织经验开始」。

负载高峰：先升 tick，再增实例
2

tick 速率

调度机制 · 降 tick

不增实例，降背景 agent 的推理频率让出槽位。成本压力下的第二档手段。

成本压力：先降档，再降 tick
3

模型档位

LOD 调度

高峰期关键路径用大模型、背景降小模型。成本压力下的第一响应——减实例有状态成本，排在最后。

顺序：降档 → 降 tick → 减实例

serverless bill shock 在本架构中结构性不可能。弹性扩缩在预算继承树内进行，总量被根预算物理封死——最多把预算烧完，然后 80% 预警、挂起（议题 8 语义接管）。scale-to-zero = 挂起而非销毁：checkpoint 保留，回暖即恢复，记忆连续；预热池 = 预 spawn + KV 前缀缓存预热。

多租户 · 租户 = 三棵树的根

组织 = spawn 树、预算树、namespace 三棵树的根。租户接入 = 签发根信封 + 根预算 + 根 namespace（衰减链的顶端）。隔离天然成立：namespace 互相不可见，预算互不可动。

计量归账：账本天然按 agent 记账，租户级汇总是用户态会计服务。

吵闹邻居 · 共享物理层

逻辑隔离有了，但租户共享推理槽位与内核。加权公平共享（cgroup shares 层级化：租户份额 → 租户内再分，权重是 sysctl 可写参数）+ 多维配额挂租户根：

credits agent 数上限 spawn 速率 黑板存储 消息速率

Principles/ 06

从 Unix 继承的四条设计原则

01

机制 / 策略分离（微内核路线）

机制在内核，策略在用户态，内核只留非留不可的。判定测试：若某机制错了或被绕过，安全或核算是否失效？是否需要在陷入点上原子完成？两关都过才入内核，否则一律用户态。

02

Multics 警惕：抽象少而准

不自上而下设计完美内核。系统调用超过约 30 个就是过度设计（当前 22 个，通过测试）；进程类型只有一种（LLM 可选，议题 13）。赢的那个是抽象最简加生态位最对的。

03

内核从不信任，只设界

policy is advisory; invariants are physics。内核强制不变量（预算守恒、公平性下界、衰减包含），LLM 驱动的策略只能在界内调参；内核不管信念，只管共享状态和原语。

04

抽象比稀缺长寿

今天为稀缺设计的抽象，在富足时代仍是地基。进程 / 虚存 / 文件如此，agent / 上下文 / 预算亦然——规模是压力测试，通用才是宗旨。
