## 断言与覆盖边界

- `plain_endpoint_1000_round_single_connection_zero_disconnection` 和 `authenticated_endpoint_1000_round_single_connection_zero_disconnection` 各在同一条 OS 连接上完成 `1,000` 轮。`five_services_interleave_on_one_authenticated_connection` 在同一认证连接验证 `ServiceDirectory`、`WaitControl`、`OperationControl`、`ChannelControl` 和 `SystemControl`。IPC 的两个 `authenticated_session` 用例验证真实握手后的多轮 principal 传递与空闲关闭。[daemon 用例](../../../crates/nlos-system-control/tests/daemon_session_mux.rs)、[IPC 用例](../../../crates/nlos-ipc/tests/session_mux.rs)
- `wal_multi_round_connection_writes_one_receipt_per_round_plus_one_handshake`、`wal_authenticated_multi_round_adds_exactly_one_handshake_receipt` 和 `wal_single_shot_baseline_writes_two_receipts_per_connection` 分别断言明文单连接 `1,000`、认证单连接 `1,001`、认证单次连接基线 `2,000` 个持久写事务。事务口径为 `clock-authority.db` 中 `wall_receipts` 行增量，每次独立命令或握手各写一行。
- `idle_timeout_fail_closes_plain_connection_and_endpoint_survives`、`idle_timeout_fail_closes_authenticated_connection` 断言空闲后旧连接关闭、新连接可用。`inter_frame_pause_longer_than_the_frame_budget_is_served` 验证帧间静默和帧读取超时分别计时。进程内 `serve_connection_serves_rounds_until_client_closes` 观察 `ClientClosed`。新增 `serve_connection_fails_closed_on_partial_header_or_body` 对截断前缀和截断帧体各覆盖对端先断开及保持半帧到期，均无分派。
- IPC 的 `rejection_suite` 三项断言超限帧、不可解码帧各计一次拒绝并可继续，以及窗口内前八次答复、第九次无答复并计入 `rejected_frames = 9`。真实端点 `daemon_endpoint_rejects_over_limit_frame_and_keeps_serving` 混合一次超限与七次畸形拒帧，断言 `InvalidArgument / DoNotRetry` 和中性请求 ID，随后第九次断开。来自同一进程的第二连接可独立拒帧并继续合法交换。运行时窗口常量断言为 `60s`，真实端点用例的拒帧均在窗口内。老化单测向真实拒帧处理函数预置一条已超过 60s 的记录和七条新记录，断言第九次累计拒帧仍保持连接，下一次才断线，累计统计保持为十。该单测覆盖已过期和未过期两侧，未测恰好 60s 的等号。 [IPC 拒帧老化单测](../../../crates/nlos-ipc/src/lib.rs)
- `authenticated_wait_face_binds_mutation_keys_to_the_verified_principal` 验证同一主体重放保持同一 Wait ID，不同认证主体使用相同键得到不同 Wait ID。`session_budget_closes_newcomers_above_the_cap_and_frees_on_release` 验证 Windows `63` 条居民会话完成交换，第 `64` 条无法交换，释放既有会话后新连接可接入。Unix 门限为 `64`。首次直接移植在 Windows 把内核完成 connect 的第 `64` 条错算为活跃会话，拿错释放对象，因此失败。测试现以一次成功交换确认每个实际活跃会话。
- 其他 IPC 断言包括 pre-gate 拒绝不匹配的 peer、拒绝零 idle、每轮调用一次 handler，以及转发响应的请求 ID 不匹配时关闭。daemon 还校验零 idle 装配失败、两端点目录通道绑定、WaitControl 与 OperationControl 结果以及五路路由的失败语义。

该回执保留本地 Windows 候选实测和同 SHA 的历史 Unix 基线证据。当前状态由交付计划和阶段 E 台账记录。
