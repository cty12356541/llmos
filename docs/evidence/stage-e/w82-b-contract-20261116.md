## 3. 裁定前 Blob 方案与替代论证（历史提案；最终采纳范围见 §6）

### 3.1 C1：引用与字节传送边界

**已观测冲突：** proto 文件头和设计 §5.1/§5.2/§12.2 承诺“任何 SABI 帧无载荷字节”，同一 proto 定义 `ReadReferenceResult.chunk: bytes`，设计又要求接收进程逐块获取原始文件。普通 unary SABI 回包中的 `bytes` 不能同时满足零字节入帧。

**推荐最小修订：** 应用消息只传 `nlosref://<32hex>`；只有 `blob_reference.read_reference` 的已授权响应携带一个受限块。内容不写普通请求/响应日志，摘要、reference ID、大小、偏移作为可审计元数据。仍逐块校验 TTL、吊销、计数、holder 和文件完整性；仍不增传输层重组状态，也不提高任何帧上界。

**变化与风险：** 必须删除“任何 SABI 帧无字节”的机密性承诺。握手证明主体，不自动加密本地传输；不得把认证 IPC 描述成端到端加密。新增的原始字节可见面为 Blob 响应和已授权接收者，必须由维护者明确接受。

**替代：** 保持所有 SABI 帧零内容字节，另设计 fd/共享内存或受控文件数据面。它需要 Windows/macOS/Linux 句柄移交、接收者绑定、撤销与清理契约，并调整现有 `chunk` 响应；不是本次最小实现，也不能沿当前 proto 直接开 B4。加大帧界仍不接受。

### 3.2 C2：完整编码界、块界和摘要边界

**硬界不变：** `MAX_BLOB_REFERENCE_PAYLOAD_BYTES = 65536` 限制完整 service message 的 protobuf 编码，含 schema、chunk、offset、digest。外层 Envelope 仍另受 1 MiB 上界约束，不能把二者混成“整个 Envelope ≤64 KiB”。

**实测：** 使用当前 checked-in TypeScript generated message 和锁定的 `@bufbuild/protobuf` 真正编码。canonical identity 为 name=`nlos.sabi.BlobReference`、major=1、minor=0，无扩展，其编码 27 bytes。32-byte digest 时：offset=0 的 65536-byte chunk 编成 65603 bytes；offset=`u64::MAX` 编成 65614 bytes。offset=0 最大可容 chunk 为 65469；offset=`u64::MAX` 为 65458；各自加 1 byte 后恰为 65537。见 `blob-encoded-boundaries.json`。

**推荐有效块：** `BLOB_MAX_CHUNK_BYTES = 65408`（64 KiB−128）作为 v1.1 服务/SDK 约定上限，mint 要求 `1 <= max_chunk_bytes <= 65408`，其值成为此令牌的固定分块尺寸 `b`。128 是工程余量，不是安全证明；安全证明为：

```text
canonical schema field = tag 1 + length 1 + identity 27 = 29
nonempty chunk field   = tag 1 + length-varint <=3 + b <= b+4
offset uint64 field    = tag 1 + value-varint <=10 = 11
SHA-256 digest field   = tag 1 + length 1 + digest 32 = 34
max encoded payload   <= b + 78 <= 65486 <= 65536
```

响应服务必须构造 canonical identity，不回显请求中的扩展 ID。未知非关键请求扩展仍按既有规则保留/转发，不能拿上述上界批准任意扩展的响应。所有响应最终仍调用已有 bounded encoder，任何未来字段/扩展增长以实际编码长度为准，不依赖余量假设。

**摘要/偏移语义推荐：** mint 对每个固定 `b` 块保存 SHA-256，末块可短；每次 read 从钉住 fd 完整读出对应块，先与 mint-time digest 比较，再返回同一块及其 digest。必须 `offset % b == 0`；`length_bytes` 表示接收上限且应不少于本次实际块长、不得超过 65408，太小/不对齐请求 typed 拒绝，绝不返回未验证的子片段。末块返回其实际长度；`offset == size_bytes` 可返回空 chunk/空内容 SHA-256 作为 EOF（同样重新鉴权、计入已接受读次数），`offset > size_bytes` 拒绝。空文件直接走 EOF。默认 SDK 请求 length=65408，按返回实际字节数递增 offset，因此不需猜 token 的 b。

**影响：** “每 64 KiB 摘要”改为“每个令牌有效块 b 摘要”，任意 range read 收紧为对齐整块读取；这不是仅注释勘误，需维护者接受。若要保留任意 range，替代方案为先完整验证涉及的 mint-time backing blocks，再返回子区间并新算 chunk digest；此时返回 digest 不再等于 mint-time 单块 digest，需另一套明确语义和向量，当前不推荐混用。

**必须验收的正负向向量：** b=1/65408；max_chunk=0/65409/65536 拒绝；offset=0/127/128/16384/`u64::MAX` 编码边界（不意味着最后者是合法文件偏移）；encoded=65536 接受、65537 拒绝；有额外 response extensions 时不得复用 canonical 长度结论；完整块、末尾短块、空文件、EOF、offset越界、加法溢出、非对齐、请求上限小于实际块；在已钉 fd 上原地改写与换路径分别测试，任一 digest 不匹配须零字节交付。

### 3.3 C3：发送者、接收者与引用授权

**已观测冲突：** mint 现有字段 1–7 没有接收者，令牌却只允许 holder 读取；要求不同主体 sender→receiver 的演示，没有可表达 recipient 的公开路径。reference ID / URI 只是对象身份，不能充当 bearer grant。

**推荐 additive 字段：** `bytes recipient_principal_id = 8`，非空必须 16 bytes；空值保持 sender 自用，向前兼容已有 mint golden 向量。服务从握手得 sender，校验其文件围栏和 mint 权；recipient 从 Identity authority 解析为活动主体。mint 签名/幂等摘要覆盖 recipient、workspace/path identity、文件全文 digest/大小及读数/块界/TTL。令牌分别保存 issuer=sender 与 holder=recipient，不将两者混为一人。

read 每次验证认证 principal == holder，加独立有效 Blob 服务授权，并重新核对令牌的吊销/TTL/读数/文件块 digest；仅知道 URI、reference ID、root CapabilityId 或可伪造 caller 字段均不能读取。发送者保留主动撤销/release 管理权；接收者可以释放自己的令牌、不能再委托。release 的两种主体权限须独立验证并留下不可变回执。

**兼容与影响：** 新增字段、生成代码、manifest 字段登记、签名消息、DDL issuer/holder 列以及新正负向向量同一原子变更。保留 v1.0 全部字节和既有 v1.1 不可变向量；新增独立向量覆盖 recipient。新服务遇到空 recipient 按 sender 自用，不能把旧客户端无字段行为解释成公开共享。

**替代：** 不加 wire 字段，由 daemon 预置且可审计的 TrustedRecipientBinding 为一次 mint 指定唯一接收者。这可做库级双主体测试，但纯 wire 客户端不能自主选接收者；配置来源、授权、有效期和唯一性仍须 INT 明确定义。禁止从 `session_hint`、客户端自报 caller 或裸 URI 推断此 binding。把 holder 检查删除以实现双主体不予接受。

**向量：** A 有 mint 权、绑定 B，B 有读服务权→成功；A 本人不因 issuer 身份自动取得 B 的读权；C 拿到 URI→拒绝；伪造 B caller/错误会话/过期或已撤销 B→拒绝；recipient 长度15/17、未知或非活动主体→拒绝；同键同全部摘要重放、同键换 recipient/digest/约束→Conflict；B 再委托→拒绝；A撤销、B释放后下一块拒绝；单级引用授权不得扩出 sender 的围栏、TTL、块界和读取预算。

### 3.4 C4：重启、引用恢复和资源界

**推荐 fail-closed 重启语义（待维护者接受）：** fd 是进程资源，不能从持久 path 恢复原来的文件对象。重启后所有旧存活引用进入不可读状态，保留 mint/读/吊销审计；不得重新打开原路径“恢复”旧令牌。sender 必须重新 mint，新 fd、新摘要、新 reference ID。daemon slot 表同样按会话失效；新握手只有在 authority 当前 holder/generation/期限/祖先检查通过后才可重建映射。仅持旧 root ID 或 reference ID 不构成恢复授权。

必须逐项配置并测试，而不能只写“有界”：每主体每窗口 mint 数、每主体/全局活跃令牌及 fd 数、最大 TTL、max_reads、每会话/全局并发读数、单文件 bytes 与 chunk-manifest 条目上限、每主体/全局 manifest 元数据总量。mint 可流式 hash 文件，但不封顶大小/块数会使摘要清单和扫描成本无界；不得用“文件天然有界”替代资源上限。

验收至少包括：恰好达到各配置界成功、加一拒绝；乘法/加法溢出拒绝；TTL/release清理 fd 与活跃元数据；重启旧 token/旧 slot 拒绝，新 mint 成功；并发读数受限；单调读数与吊销竞争不超预算。记录不删除的审计表仍随时间增长；此已接受的长期磁盘增长边界不能宣称为永久容量硬界。采用推荐块界后，在途内容空间可按并发读上限×(一个验证块+编码结果+外层Envelope有界开销)估算，实测仍归 B4。

### 4.2 库层可信注入边界（接口责任，不是已实现类型）

B2/B3 允许新增库内 context/authorizer trait，但 handler 不得仅收 Envelope 并信任其 caller。逻辑输入必须包含：已验证 principal；绑定的 application/process+generation；会话实例身份；已解析的权威 capability handle；authority-issued 时间；当前请求 body/input digest；service/method 与目标资源的明确授权结果。实际 Rust 类型/函数名由各 owner 定义后签认，不把本清单误当已有 API。

daemon 独占从握手构造可信 context 的生产入口；库测试可以通过受控 fixture/authorizer 注入。payload caller 必须逐字段匹配握手/会话绑定。授权接口必须覆盖 service、method、target/purpose、input digest、期限、generation 和 holder；未经授权时零 provider 发包、零 guest 启动、零状态改变。库测试 authorizer allow/deny 分支不能冒充真实 authority 端到端验证。

**slot 规则：** daemon 每会话 `u64 slot→CapabilityId(16B)`，容量64、LRU且使用中 pin；逐出只删除本会话映射。每次使用复验 authority 当前generation/holder/有效期/祖先吊销。`slot` 字节不得直接解释为 CapabilityId；跨会话复用、重启后旧slot、未知slot/旧generation均拒绝。`LLMOS_ROOT_CAPABILITY_SLOT` 仍按 D7 为严格32位小写hex权威ID，非槽位号；C 已发现的任意字符串/`adapter-slot-token` 夹具须修正并做负向测试。

Blob `reference_id` 属于独立令牌命名空间；重新解析 reference 只能找回令牌对象，不能由它重建或授予 CapabilityId 的会话映射。设计 §5.4 的“被逐出后以 reference_id 重新解析”必须受此界限约束；服务 capability 重新导入仍走已认证 holder 的 authority 校验。

**授权待签认：** 当前 `nlos-capability::CapabilityRights` 只有 `SEMANTIC_APPEND/RETRACT/ADJUDICATE/DELEGATE`；target 只有 Namespace/Task。不能虚构已有 LLM/Tool rights 位，也不能让任意现有权位自动批准这两个服务。INT 要明确现有 capability+purpose/target 到服务方法的政策，或另行批准扩展；在此以前真实 daemon 面保持 fail-closed。

### 4.3 B2 child binding 与 B3 Operation 接线

B2 的 account/operation/idempotency 派生必须基于可信 principal/会话/请求摘要，不能基于 session_hint 自授。`attenuate_budget` 现有请求只有 child_limit/valid_until，响应只有 granted_limit/valid_until，缺少可选/返回的 child身份或 capability。库可实现明确 `TrustedChildBinding(parent_account, child_account, child_principal/session, generation, expiry)` 输入的衰减与父≥子性质测试；caller 不可自行构造它。INT 必须指定 binding 来自受控进程启动/握手注册、或经过裁定的 additive wire 扩展。未有 binding 时方法 typed 拒绝，不静默选择 caller 自报账户，不把无可消费返回值的内部 child 记为端到端完成。

B3 的 invoke 必须将服务内持久操作记录与公共 OperationReference 绑定；OperationControl.cancel 必须路由到同一执行实例及 generation，杀未启动 guest→CancelledBeforeEffect，已运行→EffectUnknown，完成→Completed。未知/跨主体 operation、同键异摘要、Dispatched/EffectUnknown 盲重试均拒绝；重放返回原内容或可解析内容寻址，不另起 guest。Operation/Wait wiring 完成前可以闭合库级测试，不能声称客户端可取消。
