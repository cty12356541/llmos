# W82-B4-CI-CHECKPOINT-TIMING / Attempt 20261116

## 原 CI 失败与诊断

Windows job 133210177429 在源码 `9cce6c77e8f29ea44a080c2adf26f2fc8c745fec` 上通过了 `DeadlineExpired` 匹配，随后整段 API 用时 411.9058 ms，触发旧的 200 ms 断言。后续零回执及同键恢复断言未执行。原始 CI 日志保留在 [job-133210177429.api.log](services-native-ci-fix1/job-133210177429.api.log:1478)。本机对原测试精确执行 12 轮全过，与同进程的 4,096 次 WAL/FULL 读取用例并行执行 3 轮，每轮两项全过。

持有读快照时，真实 SQLite TRUNCATE 可以先写主库，完成回填后仍因读锁返回 BUSY。本机 fault VFS 使生产路径在首个回填写入返回 `SystemIoFailure`。清除故障后 0 ms busy timeout 的观察连接返回 `(1,67,67)`，WAL 仍超窗口。生产短请求 20.3899 ms 到期，回执计数不变。释放快照后同键成功写入 1 条回执。原 CI 没有阶段时序，411.9058 ms 的具体归属仍未定位。同步 SQLite I/O 和宿主调度可能影响整段 wall time，SQLite busy handler 和应用层退避是可独立验证的受控等待。[完整诊断](b4-ci-checkpoint-diagnosis.md) · [探针输出](b4-ci-checkpoint-logs/profile-run.txt)

## 候选改动

- `tests/blob_reference.rs` 在原 WAL 超窗和真实读快照下，使用已有 fault VFS 注入首个 `xWrite` 错误，实际生产读返回 SQLite `SystemIoFailure`。关闭 fault 后观察到 BUSY、全部 frame 已回填和 WAL 仍超窗，再执行生产 20 ms 请求，验证精确 `DeadlineExpired`、持锁期间零新增回执、释锁后同键成功且持久回执恰增 1 条、签名 release。整段 API elapsed 保留为诊断输出。
- `src/blob_ledger.rs` 的新 `cfg(test)` 单测读取实际 writer 的 `busy_timeout`，在 action 内为 0，注入有类型的 `BlobError::Busy` 后恢复初始 250 ms。
- `src/blob_reference.rs` 将原 `Timing::pause` 的计算等价提取为私有 `retry_delay_at(now)`。仍计算 `min(1ms, deadline - now)`，到期则返回错误，sleep 结束后仍检查 elapsed。新单测使用显式 `Instant` 覆盖 1 ms、距截止 250 µs、正好截止、晚于截止。产品时限、权限、计费和持久模型维持接受版本。
