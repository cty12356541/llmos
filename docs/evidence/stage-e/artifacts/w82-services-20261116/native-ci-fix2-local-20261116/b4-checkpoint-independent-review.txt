## Spec compliance

1. **整段 elapsed 与受控等待分开验证：符合已裁定边界。** 旧 Windows job 的 `DeadlineExpired` 匹配先通过，411.9058 ms 在后续整段 API stopwatch 断言失败；该观测不能定位具体慢阶段。新用例只把这一 stopwatch 改为诊断输出，没有提高阈值、修改产品 deadline 或声称确定了原 CI 根因。SQLite 的同步回填/刷新、OS I/O 和线程调度不因此获得整个请求 20 ms 或 200 ms 的硬 wall-time SLA。
2. **真实 checkpoint 路径保留且增强。** `tests/blob_reference.rs:2040–2084` 使用实际 fault VFS 创建 authority，WAL 实际长度超出由当前 page size 算出的 64-frame 窗口；独立连接 `BEGIN` 后执行真实 SELECT 建立并持有读快照。`assert_checkpoint_backfill_attempted`（2105–2126）在生产服务 read 上让首个 VFS `xWrite` 返回 IOERR，断言实际观察到写入和精确 SQLite `SystemIoFailure`。关闭故障后另一个 busy_timeout=0 的连接验证 `(busy=1, frames>0, backfilled=frames)`，且 WAL 仍超窗。这证明后面的重试用例面对真实不能截断的 WAL，不是空 checkpoint 或模拟 Busy 返回。附带 profile 的实际 `(1,67,67)`、写入计数 1 与 WAL 276072 B 支持诊断，但不外推原 CI 的慢阶段。
3. **截止失败、零回执及恢复闭环仍是硬断言。** `tests/blob_reference.rs:2086–2102` 仍在可信 mono=100000000 ns 的 fixture 上传入 deadline=120000000 ns，必须返回精确 `DeadlineExpired`。receipt 数量现在在释放 reader 之前检查不变；ROLLBACK 后相同主体、reference、offset/length、idempotency key=100 成功，持久 receipt 恰增一条，再执行真实签名 release。此前故障读也使用 key=100，因此零增长及后续同键成功覆盖两个错误路径没有留下成功 receipt。新用例不再因无依据的整段耗时上限提前 panic 而跳过这些断言。
4. **受控 SQLite 排队有直接回归门。** `src/blob_ledger.rs:692–712` 在真实 Connection 上调用生产 `with_blob_writer_settings`；初始 timeout=250 ms，action 内通过实际 PRAGMA 断言 timeout=0，返回有类型的 `BlobError::Busy`，调用后仍得到该错误且 timeout 恢复为 250 ms。实际 mutation 将生产设置改为 250 ms，测试以 left=250/right=0 退出 101；恢复候选后 1/1 通过。这不是对常量的孤立断言，也不依赖宿主调度精度。
5. **应用退避预算有确定性回归门。** `src/blob_reference.rs:1080–1099` 对传入的显式 Instant 验证正常 1 ms、仅剩 250 µs 时收紧，以及等于/超过 deadline 时精确拒绝。去掉 `.min(remaining)` 的实际 mutation 以 left=1 ms/right=250 µs 退出 101，恢复后 1/1 通过。该门验证生产 pause 所用预算计算；它不宣称 OS 的实际唤醒时刻绝不晚于请求的 sleep。

## Code quality

**生产提取语义等价。** `src/blob_reference.rs:1050–1060` 仍只采样一次 `Instant::now()` 来计算 `stop_elapsed.saturating_duration_since(now)`；零剩余量仍在 sleep 前返回同一错误，非零剩余量仍请求 `min(1 ms, remaining)`，sleep 返回后仍执行原 `check_elapsed()`。新增函数为私有方法，未引入新时钟、重设 stop_elapsed、额外 sleep、锁或错误映射。其余生产差异为空：ledger 仅新增 `cfg(test)` 模块，没有更改参数、DDL、权限、会计、公共 API 或依赖。

**故障注入隔离与清理可接受。** 新用例使用同一集成测试二进制内既有 `FAULT_LOCK`，检查到所有同进程 fault-arm 测试都在此锁内；普通 fixture 使用默认 VFS。新 helper 在 read 返回并取得写计数后、执行任何新断言之前 disarm；断言失败不会把已注入故障留给后续正常操作，锁也覆盖 fixture 连接的生存期。observer/snapshot 为独立普通连接，故障只覆盖被测生产连接。没有增加全局默认 VFS 替换或未锁的异步注入线程。

**跨平台验证没有静默放宽。** 页面窗口从实际 page_size 推导，不固定某一主机 frame 数量；没有新增平台 ignore、时间阈值或错误吞并。held-reader/BUSY、实际 xWrite、全回填、WAL 超窗和 receipt 结果都必须成立。Windows 本机原始日志可确认通过；其他原生平台仍由最终 CI 验证。本报告不把 fault VFS 的 IOERR 当成 xSync 故障、物理断电或完整持久性框架的证明。
