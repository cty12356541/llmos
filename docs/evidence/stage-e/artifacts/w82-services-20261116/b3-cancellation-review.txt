## 原 finding 处置

**P1 跨服务共享 writer 的取消只写 journal、不终止 host：ADDRESSED。**

`tool_service.rs:705` 的 `observe_dispatch` 读取同一 operation handle 的持久状态，只允许原 Dispatched receipt 继续运行；CancelRequested 转为取消，其它状态或读取错误使执行停止。该观察在 `tool_service.rs:668` 的最后 clock/policy 授权之前执行，避免新增 store 读取等待直接老化最终授权快照；同时作为 callback 交给真实 host 等待循环。

`tool_process.rs:67` 的 callback 位于 child mutex 临界区之外。另一服务实例持久提交 CancelRequested 后，执行 owner 在下一次正常返回的观察中调用本地 `cancel`，终止并 reap 自己拥有的同一 child。这里没有让另一服务伪造 ChildControl，也没有引入第二执行。`CancelRequested` 返回值明确表示已持久受理；唯一终态仍由 executor 的既有 receipt CAS 收敛为 EffectUnknown，符合取消请求不等于无副作用的语义。

新增真实共享 journal/host 回归覆盖：跨实例取消、stale generation 拒绝、两实例同 key 不再 spawn。已查阅 `green-shared-cancel-final.log`：测试通过，单次 cancel 到回收和持久终态为 **13 ms**；原 500 ms 红例保留，不能将该实测改称固定最坏上界。

## 修复引入的错误、锁与时序检查

**New fix breakage：未发现。**

- 新增持久查询不持 child mutex；查询返回后才取得 child 控制锁执行 kill/reap，未引入 store/child 的反向嵌套锁序。现有本实例 cancel 仍可直接到达 child。
- 已 dispatch 后发生跨实例取消与 spawn 交错时，executor 的观察/原有 finish CAS 保持保守 EffectUnknown；没有回退成 CancelledBeforeEffect。完成先提交或取消先提交仍由持久 revision 竞争决定，late completion 不覆盖终态。
- host 已退出时 wait 可以先返回退出状态，但完成持久化仍经过原 CAS；新增完成前 barrier 测试覆盖取消先提交，另一次调用覆盖完成先提交。
- 持久查询错误映射为 typed StoreError，并通过本地 cancel 先停止 host；随后尝试保存 EffectUnknown(HostLost)。查询/写入仍不可用时保留 durable dispatch/cancel fence，不能据此猜测无效果；恢复语义未被改写。新增读失败测试覆盖真实 host 停止和可写情况下的 HostLost 墓碑。
- catalogue 使用无状态观察 callback，保持原执行/授权/输出限制。HostStop 错误映射变更没有将 pipe/guest/deadline 失败变成成功，也未吞掉持久观察错误。
- 20 ms 是每次正常查询返回后到下一次观察的配置间隔。可替换存储若阻塞，实际观察延迟仍受其 I/O 与 OS 调度影响；代码、Fixround 1 回执及 Evidence 已说明该限制。本复审不声称任意 adapter 具有 20 ms 的强取消 SLA。
