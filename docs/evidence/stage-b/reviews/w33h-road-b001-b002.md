## 2. ROAD-B-001 构造性证据评估（本评审核心问题）

**问题**：W33-B 样板 + W33-A 工具链 + W33-C conformance kit + W29-E 迁移 runner + W30-D teardown 链，是否构成该门按其行措辞的构造性证明？

**行措辞**（§6.5.1 B1-5 / §6.5.3 W33-B 验收门）：「非内核视角开发→签名→安装→运行→更新→卸载」+「全程不触内核内部 API」= 退出门构造性证据。

**评估：构成，但为带四个具名边界的构造性证明（PARTIAL）。**

成立的部分：

1. **非内核视角成立**：样板 `sample-app-driver` 只 import 公共 crate（nlos-application/artifact/process/runtime/runtime-tokio/slice-k/task/types + crates.io sha2/tokio），零内部模块、零私有 API、零派生公式复制（[B-APPLICATION-007 §1](../b-application-007-third-party-sample.md)，自有幂等/时钟键按独立域分隔派生）。工具链半边同构：CLI verify 全部委托权威验签管线、不拥有自有验证逻辑（[B-ARTIFACT-007 §1](../b-artifact-007-package-sdk.md)）。
2. **全周期六环齐全且真机贯通**：develop（开发者目录）→ sign（keygen/build 域分隔签名）→ install（receipt digest-binding，gen 1）→ run（durable task/operation/fiber + TaskCommitReceipt + background task/process binding 登记 + 真实子进程）→ update（W29-E migrate→step×2→health probe 恰一次→原子切换 gen 1→2）→ uninstall（先见证 W27-D 门 typed 拒绝，再 W30-D teardown：真实 SIGTERM 杀死 Os 替身→crash terminal→cancel→过门卸载；负门：卸载后 run fail-closed、`kill -0` 确认进程消失）。`lifecycle.sh` exit 0（§4.1 输出逐行断言）。
3. **链条各环的语义深度不是 happy-path 薄壳**：update 走的是带冻结基线/目标 + 健康检查 + 单事务切换的迁移引擎（非直接 CAS 通道）；uninstall 走的是活动门 + teardown 链（非裸 terminal CAS）；conformance kit 对「任意 v1 包文件」独立复检结构与签名一致性（42 规则）。

具名边界（使证明是 PARTIAL 而非 FULL，均已在证据文件登记，本评审原样沿用）：

1. **载荷执行面未做**：manifest `executable` entry 字节不被真实执行——「运行」的证据对象是公共任务/操作/纤维面，载荷以 artifact 形态可消费；内核侧载荷执行属后续车道（[B-APPLICATION-007 §5](../b-application-007-third-party-sample.md) 首条）。
2. **Os 服务替身是 `sleep` 子进程**：真实子进程、真实 SIGTERM、真实死亡，但非内核托管服务进程；supervisor registry 内存态，pid 由脚本跨进程携带按重启模式重注册（§5 第二条；[B-SLICE-K-001 §15.4](../b-slice-k-001-end-to-end.md) 同源边界）。
3. **消费端接线是库驱动**：`nlos package install` CLI 子命令仍未做，install/run/update/uninstall 消费端由 `sample-app-driver` 库 API 承担（§5 第三条）。
4. **模板编译只到 proposal**：`compile_task_templates` 未接 `apply_plan_revision`（plan authority 接线后续车道；§5 第四条）。

**对照门原文的外推上限**：门说「一个不了解内核实现的第三方**能**开发、安装、更新和卸载未预设 Application」——当前证据支撑的声明面是：单节点、单写者、macOS/arm64 实跑 + 非 Unix 契约道（未本机实测）；不支撑三平台实证、多 principal/多方审批、载荷执行、生产 trust-root。6.5.5 条件 1 要求的三平台 CI 维度尚未由 W33-A/B/C 落实（各文件「未运行项」显式登记，波次屏障统一跑）。
