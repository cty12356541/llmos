# llmos 设计问题与理论风险清单

> 版本：v1.0
> 日期：2026-07-26
> 来源：对议题 1–25、架构总纲 v0.3、experiments/ 的理论准确性深挖
> 用途：设计评审、工程优先级、对外表述修正；**不是否定立项**，而是标注已知裂缝与过度主张
> 严重度：P0 阻塞核心主张 / P1 影响万级或安全 / P2 影响完备性或生态 / P3 表述或后置项

---

## 一、问题分级说明

| 级别 | 含义 | 典型处置 |
|---|---|---|
| **P0** | 若不修补，核心设计主张在理论上或工程上不成立 | 必须原型验证或改表述 |
| **P1** | 万级规模、安全、预算守恒等关键路径存在缝隙 | v1 前需设计补全或实证 |
| **P2** | 影响通用性论证、生态竞争、长期可维护 | 文档修正 + 分阶段实现 |
| **P3** | 表述过度、遗留开放项、部署期问题 | 改文档或明确后置 |

**状态标记**：`未决` | `部分缓解` | `已设计未证` | `已 mock 验证` | `已知接受`

## 二、论证与表述过度（Overclaims）

### O-01 · 「LLM 调用 = 系统调用」是唯一正确解

| 项 | 内容 |
|---|---|
| 关联 | 议题 6、总纲 §3 |
| 问题 | 文档称陷入层位置为「唯一正确解」。理论上存在 sidecar 代理、out-of-band 审计等替代；真正必要的是**跨越私有边界时的不变量强制**，而非 trap 这一实现形态本身 |
| 严重度 | P2 |
| 状态 | 部分缓解（exp1 证 sidecar 可行，但未证分布式形态） |
| 建议 | 对外改为「**最小充分控制点**」；trap 是首选实现而非逻辑必然 |

### O-02 · 「构造性证明 / 语义图灵完备已完备」

| 项 | 内容 |
|---|---|
| 关联 | 议题 20、25；索引「C 类三问关闭 → 公理齐备」 |
| 问题 | 当前是**公理草稿 + 八原语覆盖草图 + 16 模式重构测试**，不是 Church-Turing 级汇聚证明。议题 25 自述证明义务未竟（O*NET 普查、引理 3 形式化） |
| 严重度 | P2 |
| 状态 | 未决（议题 25 讨论中） |
| 建议 | 对外称「**结构性通用框架 + 可表达性论证**」；「完备性定理」仅用于内部，并附边界与反例清单 |

### O-03 · 「人类组织 = 语义计算机」作为存在性证明

| 项 | 内容 |
|---|---|
| 关联 | 议题 20 §6 |
| 问题 | 组织大量失败、非计算、受制度约束；该论点是**启发式汇聚证据**，非逻辑证明。用户已在 Q2 选择更严格的构造性路径，但组织论证仍散见文档 |
| 严重度 | P3 |
| 状态 | 部分缓解（构造性路径取代，但未全文清理） |
| 建议 | 降级为「**存在性类比**」，不作为定理引用 |

### O-04 · 「历史类比 → agent OS 必然出现」

| 项 | 内容 |
|---|---|
| 关联 | 议题 4 |
| 问题 | 类比是强启发式，非因果律。反路径同样合理：K8s/Dapr 扩展、推理引擎内化调度、MCP/A2A 协议栈吸收「内核」职能 |
| 严重度 | P2 |
| 状态 | 已知接受（文档有 Multics 警示，但未写竞争路径） |
| 建议 | 增加「**生态分叉情景**」章节：独立内核 vs 控制面扩展 vs 协议栈下沉 |

### O-05 · 「议题 3 六死因全部闭合」

| 项 | 内容 |
|---|---|
| 关联 | 议题 11、18；索引里程碑 |
| 问题 | 「有解」≠「已证」。Topic 兴趣过滤未细化、Blackboard 分片策略未原型、语义层零代码——六死因在**设计层**有对应机制，**工程与定量层**多处未闭合 |
| 严重度 | P1 |
| 状态 | 已设计未证 |
| 建议 | 区分「设计覆盖」与「验证闭合」；索引与总纲状态字段分开标注 |

### O-06 · 「8 抽象语义全部闭合」

| 项 | 内容 |
|---|---|
| 关联 | 议题 5–9、21–24 |
| 问题 | C 类语义层（原子/link/规格）仅有议题定案，**无实现、无与内核集成的原型**；Topic 谓词 eBPF 化未设计 |
| 严重度 | P2 |
| 状态 | 已设计未证 |
| 建议 | 标注为「**运行时语义闭合 / 语义层待实现**」 |

## 三、负载无知防火墙的张力

### F-01 · 「内核永不读 content」与 embedding fingerprint

| 项 | 内容 |
|---|---|
| 关联 | 议题 13、22、24 |
| 问题 | fingerprint 是 content 的函数；内核做向量索引虽不做 NL 推理，但**不是语义无关**。声称「零语义泄漏」过强 |
| 严重度 | P2 |
| 状态 | 未决 |
| 建议 | 精确表述为「**内核不做语义推理/裁决；允许 content 导出的几何指纹索引**」 |

### F-02 · 看门狗相似度 = 「结构信号」

| 项 | 内容 |
|---|---|
| 关联 | 议题 9、13；exp2 |
| 问题 | n-gram/embedding 相似度是内容统计量，非纯结构。exp2 只验 idealized 空转，未验「有产出但错误/语义空转」 |
| 严重度 | P1 |
| 状态 | 已 mock 验证（边界有限） |
| 建议 | 改称「**弱语义启发式第一级过滤器**」；第二级监督 LLM 的 Byzantine 风险写入 SLA |

### F-03 · 「进展 = 已通过验收数/总数」

| 项 | 内容 |
|---|---|
| 关联 | 议题 23 §5.2 |
| 问题 | 验收通过可能依赖 L2 llm-judge → 进展信号间接依赖语义判断，与负载无知略冲突 |
| 严重度 | P2 |
| 状态 | 未决 |
| 建议 | 进展信号限定为「**确定性 checker 通过数** + 结构产物计数」；LLM-judge 通过单独标记，不进内核 watchdog |

### F-04 · Topic 兴趣过滤的 eBPF 类比未完成

| 项 | 内容 |
|---|---|
| 关联 | 议题 5、13；总纲 §4.5；索引遗留 |
| 问题 | 谓词编译模型、安全沙箱指令集、万级订阅 fan-out 复杂度均未定义。MMO interest management 不能直接套用（游戏实体有坐标，Topic 兴趣是语义/声明混合） |
| 严重度 | P1 |
| 状态 | 未决 |
| 建议 | 单独议题：谓词 IR、编译期/运行期边界、最坏 fan-out 上界证明或仿真 |

### F-05 · 断言级别 / link 关系枚举的累积滑移

| 项 | 内容 |
|---|---|
| 关联 | 议题 24 |
| 问题 | 宪法与四重测试已立，但「PART_OF 诱惑」「聪明内核推断」等在实现期仍易破墙。无自动化审计工具 |
| 严重度 | P2 |
| 状态 | 部分缓解（议题 24 定案） |
| 建议 | 实现 CI：`enum-governance` 检查 + 内核代码禁止读 `content` 字段的静态规则 |

### F-06 · Policy「只许 verified 进规划」的间接语义

| 项 | 内容 |
|---|---|
| 关联 | 议题 9、12、24 |
| 问题 | 内核不判真假，但 gating 在认识论层塑造 agent 行为；若 verified 标记可被生产者伪造或 L2 误判，闸门失效 |
| 严重度 | P1 |
| 状态 | 已设计未证 |
| 建议 | verified 只能由**独立验证者**或**确定性 checker** 写入；自检 verified 需 Policy 显式允许 |

## 四、Budget 与经济模型

### B-01 · max_tokens 硬顶 ≠ 完整 budget 守恒

| 项 | 内容 |
|---|---|
| 关联 | 议题 8、11；exp1 |
| 问题 | 硬顶主要约束 completion tokens。缺口：prompt 预扣误差、tool preauth 不精确、reasoning/hidden tokens、多模态、driver 少报 chunk、流式计量延迟 |
| 严重度 | P0（若宣称「物理保证无透支」） |
| 状态 | 已 mock 验证（completion 子集） |
| 建议 | 完整守恒 = **硬顶 + prompt 预扣 + tool preauth + 流式计量 + 驱动可信回报 + 负余额拒绝**；对外分开承诺 |

### B-02 · credits 与真实法币/组织财务脱节

| 项 | 内容 |
|---|---|
| 关联 | 议题 8 遗留 |
| 问题 | 内核 credits 抽象正确，但多租户财务对账、汇率、发票在部署期；跨组织清算所模式的信用风险未建模 |
| 严重度 | P3 |
| 状态 | 已知接受（后置） |
| 建议 | 部署指南单独成章；联邦场景需「**组织信用额度 + 轧差争议**」用户态模块 |

### B-03 · 挂起 checkpoint 存储租金未定义

| 项 | 内容 |
|---|---|
| 关联 | 议题 8、10；总纲 §16.1 |
| 问题 | L2 上行扩权挂起可能持续小时级；万级挂起 agent 的存储成本与 credits 扣费规则缺失 → 存储 DoS |
| 严重度 | P2 |
| 状态 | 未决 |
| 建议 | 挂起按 storage×time 扣 credits；余额不足则 degrade 为摘要 checkpoint 或 kill |

### B-04 · 份额租约与控制面故障的透支上界

| 项 | 内容 |
|---|---|
| 关联 | 议题 15 |
| 问题 | 「透支上界 = 份额大小」在节点恶意或 bug 时可能双花；需份额 monotonic ID、过期强制失效、控制面恢复后对账 |
| 严重度 | P1 |
| 状态 | 已设计未证 |
| 建议 | 形式化：**∀节点, spend ≤ issued_chunk − returned**；故障后对账协议写入 9P 控制协议 |

### B-05 · KV 实际成本记账依赖 provider 诚实

| 项 | 内容 |
|---|---|
| 关联 | 议题 8；exp3 |
| 问题 | exp3 mock 通过；真实 API 字段形态、缓存归因错误、跨请求 prefix 共享边界未实测 |
| 严重度 | P1 |
| 状态 | 已 mock 验证 |
| 建议 | 真实 provider 复验；驱动层「**保守预扣 + 事后 reconcile**」 |

### B-06 · degrade 策略的静默失败风险

| 项 | 内容 |
|---|---|
| 关联 | 议题 8 |
| 问题 | 文档已警告 degrade 危险，但 ELF 仍允许声明。小模型静默产出低质量结果 → 下游 epidemic |
| 严重度 | P2 |
| 状态 | 已知接受 |
| 建议 | degrade 必须伴随 **criticality 上限** + 产出带 `degraded` 污点 + Policy 禁止 degraded 进 verified 通道 |

### B-07 · escrow + llm-judge = 概率性合约

| 项 | 内容 |
|---|---|
| 关联 | 议题 8、23 |
| 问题 | 「任务完成释放」在语义任务上是 **probabilistic SLA**，非 logical guarantee。争议裁决仍依赖人或组织层 |
| 严重度 | P2 |
| 状态 | 部分缓解（议题 16 否每调用 escrow） |
| 建议 | IntentSpec 区分 **hard gate**（deterministic checker）与 **soft gate**（llm-judge）；escrow 默认只绑 hard gate |

## 五、随机性、容错与控制

### R-01 · Byzantine 类比不可直接套 3f+1

| 项 | 内容 |
|---|---|
| 关联 | 议题 9 |
| 问题 | LLM agent 无共同状态机；N-version 有效需**多样化**（模型/提示/harness），非简单副本多数决。3f+1 不给出冗余数量公式 |
| 严重度 | P2 |
| 状态 | 部分缓解（文档采用分档购买） |
| 建议 | 明确写「BFT 是**隐喻框架**」；关键路径需多样化矩阵而非固定 N=3 |

### R-02 · 监督 agent 的递归 Byzantine 风险

| 项 | 内容 |
|---|---|
| 关联 | 议题 9、12 |
| 问题 | 第二级监督是 LLM；恶意 trace 可攻击监督者（控制面注入）。议题 12 强制污点化，但**结构化提取本身可能被污染** |
| 严重度 | P1 |
| 状态 | 已设计未证 |
| 建议 | 控制面输入 schema 固定 + 字段级校验 + 监督者与普通 agent **物理 namespace 隔离**；关键决策 human L2 |

### R-03 · 「看似健康输出错误」无法被第一级看门狗检测

| 项 | 内容 |
|---|---|
| 关联 | 议题 9；exp2 |
| 问题 | 看门狗检 livelock，不检 wrong-but-plausible output。Hallucination epidemic 主要靠 provenance gating，未实证 |
| 严重度 | P1 |
| 状态 | 已设计未证 |
| 建议 | 增加 **exp5：污染传播仿真**（无 LLM，纯 provenance 图） |

### R-04 · 在途调用 = 控制盲区（部分闭合）

| 项 | 内容 |
|---|---|
| 关联 | 议题 11、12、15 |
| 问题 | trap timeout、取消传播、max_tokens 已设计；**长时 tool（shell）**、**provider 忽略 cancel**、**drain 迁移窗口**仍可能失控 |
| 严重度 | P1 |
| 状态 | 已设计未证 |
| 建议 | tool 调用强制 timeout + 沙箱 kill；迁移默认 drain 的上界时间 |

### R-05 · branch/join 冗余原语的使用负担

| 项 | 内容 |
|---|---|
| 关联 | 议题 9 |
| 问题 | 内核提供原语，但「何时 branch、如何多样化、如何投票」全在用户态 → 大多数 harness 不会用 → 容错设计悬置 |
| 严重度 | P2 |
| 状态 | 已设计未证 |
| 建议 | 提供**用户态参考实现**（reliability middleware）；ELF criticality 驱动默认策略 |

## 六、规模、性能与万级调度

### S-01 · 5k traps/s 算术 vs 流式/chunk 陷阱频率

| 项 | 内容 |
|---|---|
| 关联 | 议题 11、13、15 |

| 严重度 | P1 |
| 状态 | 未决 |

### S-02 · Topic 解决 O(n²) 的条件未量化

| 项 | 内容 |
|---|---|
| 关联 | 议题 3、5 |

| 状态 | 未决 |
| 建议 | exp6：Topic fan-out 仿真（谓词选择性 vs 负载）；定义「有效复杂度 = Σ subscribers × selectivity」 |

### S-03 · Blackboard 热点分片策略缺失细节

|---|---|

### S-04 · checkpoint 写放大（LangGraph 死因）在 llmos 上的转移

|---|---|

### S-05 · 10k 沙箱 / 进程回收（harness 派死因）

### S-07 · lineage / provenance 图无界增长

## 七、分布式、一致性与联邦

### D-01 · 跨机 wakeup 原子性的实现复杂度

| 项 | 内容 |
|---|---|
| 关联 | 议题 15 |

### D-03 · 联邦清算所的信用与争议

|---|---|
| 关联 | 议题 16 |

| 状态 | 已知接受 |

### D-04 · 「A note on distributed computing 一半失效」表述过强
